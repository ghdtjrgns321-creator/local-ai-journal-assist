# 11. 대시보드 — 현재 어디까지 만들어졌나

## 11.1 파이프라인 내 위치

```
생성 → 품질검증 → 수집·파생·검증 → 탐지 → 표면 → 적재 → ▶▶▶ [화면] ◀◀◀
```

**이 장은 미완성 구간을 기록한다.** 분석 엔진과 검증 체계는 완주했지만 화면은 아직 다듬어지지 않았고, 그 상태를 정확히 남기는 것이 이 장의 목적이다.

## 11.2 실제로 도달 가능한 화면 7개

`dashboard/app.py:275-315`이 import하고 호출하는 화면이 전부다(`dashboard/_state.py:61-69` `RESULT_PAGES` 7개).

```
        ▼

```

탭 라벨(`룰 기반` / `분석적 검토` / `비지도(VAE)`)이 곧 3-surface 불변식의 화면상 노출이다. 탭 전환은 nav만 담당하고 **활성 탭만 렌더**한다. 7개 패널을 동시에 평가하면 로딩이 느려지기 때문이다.

탭 순서는 2026-07-25에 `전기 비교`를 `비지도(VAE)` 앞으로 옮겼다. 전기 비교는 룰·분석적 검토와 같은 PHASE1 산출물을 전기와 맞대보는 화면이라 앞의 두 탭에서 흐름이 그대로 이어지고, 별도 실행이 필요한 PHASE2를 마지막에 두는 편이 실제 실행 순서와도 맞는다.

## 11.5 PHASE1 탭의 상태 — 4,064줄과 미검증

`tab_phase1.py`는 4,064줄이며 최상위 정의가 88개다. 4개 하위 탭(전체 요약 / 데이터 정합성 / 검토 케이스 / 통계 결과)을 담고 있고 검토 케이스가 조합 빌더를 호출한다.

**개별 함수의 동작은 전수 검증되지 않았다.** 등급 폐지 대수술 후 도달 불가 블록 310줄을 삭제했고 관련 테스트는 통과했지만, 88개 함수 각각이 의도대로 동작하는지는 확인되지 않았다. 이것이 "Streamlit을 아직 제대로 만들지 못했다"의 구체적 내용 중 하나다.

## 11.7 실증 예시 — 감사인이 지금 실제로 할 수 있는 일

현재 상태에서 데모가 어디까지 가는지 따라간다.

앱을 실행하면 **회사 선택** 화면이 뜬다. 회사를 만들거나 고르고, 감사연도를 선택하면 그 조합에 해당하는 DuckDB가 열린다(없으면 생성).

**업로드** 단계에서 원장 CSV를 넣으면 3단계 스테이지가 돈다: 업로드 → 매핑 확인 → 파이프라인 실행. 매핑 확인 화면에서 자동 매핑 결과와 애매한 후보가 나뉘어 표시되고, 감사인이 확정한다.

**실행**이 끝나면 결과 화면으로 전환된다. **개요** 탭에서 전체 규모와 KPI, Benford 요약을 본다. **룰 기반** 탭으로 가면 네 개 하위 탭이 있고, 검토 케이스 탭에서 조합 빌더를 만난다.

여기서 "비용자산화" 프리셋을 누르면 [7장](7_PHASE1-1_COMBO-BUILDER.md) 7.9절의 흐름이 그대로 화면에서 일어난다 — 몸통 1개·특징 10개가 체크되고, 일치 건수가 표시되고, 정렬된 목록이 "발화 룰" 컬럼과 함께 나온다. 감사인은 알약을 눌러 조합을 바꾸면서 건수 변화를 보고 범위를 조절한다. 다만 개별 행을 펼쳐 룰별 근거 행까지 확인하는 드릴다운은 아직 없다.

**분석적 검토** 탭은 PHASE1-2 전용 표면이다. 전표 한 장으론 안 보이고 계정·거래처를 모아야 드러나는 신호(Benford·라운드넘버 밀집도의 자기 큐 + 첫등장/희소 거래처)를 룰 큐와 **별도 큐**로 렌더한다. 이 분리가 3-surface 비병합의 화면상 구현 중 하나다.

같은 PHASE1-2 신호 중 **계정활동변동(D01)·월별비율변동(D02)은 `전기 비교` 탭 안에서** 표시한다(2026-07-25). 둘은 전기 engagement 를 붙여야 계산되는 신호라 전제가 전기 비교와 같고, 묻는 질문도 같기 때문이다 — D01 은 `계정과목 변동` 소분류에서 변동액 Top 15(금액만 봄) 바로 아래에, D02 는 `전체 요약` 의 월별 추세(원장 전체) 바로 아래에 붙어 같은 축을 계정 단위로 이어 받는다. 표시 위치만 옮긴 것이고 신호 소유권과 점수 비병합은 그대로다.

이 이동은 화면 정리인 동시에 내용 교정이었다. 옮기기 전 표는 `가중변동 1.842`, `우선순위`, `버킷` 같은 **내부 점수만** 보여 감사인이 읽을 게 없었다. finding 안에는 금액·건수·평균의 당기/전기 원값이 이미 들어 있었는데 화면까지 오지 않았다. 지금은 "당기 금액 / 전기 금액 / 변동액 / 증감률 / 당기 건수 / 전기 건수 / 건당 평균 증감률"로 바꿔, 금액은 비슷한데 건수가 급감한(=건당 단가가 뛴) 계정 같은 변화가 표에서 바로 읽힌다. D02 도 JSD 숫자 대신 "11월 → 10월, 20.8% → 62.1%"처럼 **가장 몰린 달이 어떻게 옮겨갔고 얼마나 더 몰렸는지**로 보여준다.

**임계는 전부 걷어냈다.** 두 신호에는 목록을 자르는 컷이 있었다 — D01은 가중변동 0.5(가중치도 0.5/0.3/0.2), D02는 JSD 0.3·비중변화 0.25·전표 100건. 어느 숫자도 근거를 댈 수 없었고, 그 결과 실제 데이터에서 D02는 계정 하나만 남아 화면이 고장 난 것처럼 보였다. 지금은 **자르지 않고 전부 세운 뒤 정렬로만 우선순위를 표현한다** — D01은 변동 금액 절대값, D02는 몰린 정도의 변화폭(%p). 둘 다 표에 이미 보이는 숫자가 그대로 정렬 키라, "왜 이 계정이 맨 위인가"를 표 안에서 확인할 수 있다. 유일하게 목록에서 빠지는 건 거래한 달이 한두 달뿐이라 분포를 비교할 수 없는 계정이고, 그건 신호 강도 컷이 아니라 계산이 성립하지 않는 경우다.

임계를 없애면서 **D01·D02가 전표에 달던 꼬리표도 함께 뗐다**(`account_activity_shift`·`ratio_variance_account` 배지와 case의 macro_context). 꼬리표를 달려면 "어느 계정부터 꼬리표인가"를 가르는 임계가 필요한데 그 임계를 버렸고, 임계 없이 전 계정에 달면 꼬리표가 아무것도 구분하지 못한다. 두 신호는 이제 계정 단위 순위 목록으로만 쓰인다.

**비지도(VAE)** 탭에서 VAE 결과를 별도로 볼 수 있다. 점수가 PHASE1과 합쳐지지 않고 따로 표시되는 것이 3-surface 비병합의 나머지 한 축이다.

여기까지가 현재 동작하는 범위다. 룰 기반·분석적 검토·비지도(VAE) 세 표면은 화면에서 각각 도달 가능하다. 다만 검토 큐에 판정을 기록하거나, 결과를 Excel로 내보내는 것은 **코드는 있으나 화면에서 갈 수 없다.** 데모로 보여줄 수 있는 것과 제품으로 쓸 수 있는 것 사이의 거리가 여기 있다.
