# 9. PHASE2 — 비지도 VAE와 성능 검증이 불성립한 기록

## 9.1 파이프라인 내 위치

```
                              ┌─ PHASE1-1 룰
검증 통과 DataFrame ──────────┼─ PHASE1-2 분석신호
                              └─ ▶▶▶ [PHASE2 VAE — 별도 실행·별도 표시] ◀◀◀
```

정상 데이터만으로 "정상의 모양"을 학습한 뒤, 복원이 잘 안 되는 행을 추가 검토 후보로 올리는 표면이다.

**이 장은 검증이 성립하지 않았다는 사실을 기록한다.** 이전 판까지 이 장의 제목은 "검증 실패의 기록"이었고 문서 AUROC 0.5187을 실패 수치로 적었다. 2026-07-25 진단에서 그 라벨이 부정확함이 확인됐다 — 측정에 쓴 데이터가 성능 측정에 쓸 수 없는 상태였다. 수치는 그대로 두고 **판정 이름과 원인 설명을 고쳤다.** 무엇이 바뀌고 무엇이 바뀌지 않았는지는 9.9절에 정리했다.

## 9.2 왜 비지도인가

합성데이터에서 지도학습은 순환 논증이다. 부정 라벨은 우리가 규칙으로 심은 것이므로 모델이 학습하는 것은 부정이 아니라 **우리의 주입 규칙**이다. 치트루트 감사가 이를 수치로 확인했다([4장](4_DATASYNTH-QUALITY.md)) — 단일 컬럼만으로 AUROC 0.95 이상이 18건, 시뮬레이션 로지스틱 평균 0.9978.

비지도는 라벨을 쓰지 않으므로 이 함정을 피한다. 정상 분포만 학습하고 그 밖을 표시하는 방식이라 합성데이터에서도 유효할 것으로 봤다. 이 기대는 **검증되지 않았다.** 다만 뒤에서 보듯, 라벨을 쓰지 않는다는 성질 자체는 오염된 데이터에서 점수가 부풀지 않게 막는 쪽으로 작동했다.

## 9.3 라벨 누수 차단 — 3중 방어

모델이 답을 훔쳐보지 못하게 막는 장치가 세 겹이다.

**1차: 컬럼 deny 목록**(`src/preprocessing/constants.py`)

| 상수                               |   개수 | 근거                                                             |
| ---------------------------------- | -----: | ---------------------------------------------------------------- |
| `LABEL_COLUMNS`                    |      8 | is_fraud, fraud_type, is_anomaly, anomaly_type, sod_violation 등 |
| `SYNTHETIC_ONLY_COLUMNS`           |     18 | 위 8개 + mutation 계열 6, 합성 플래그 2, 시나리오 ID, 탐지 힌트  |
| `LEAKAGE_DENY_COLUMNS_BASE`        |     15 | 단일 컬럼 AUROC ≥ 0.95                                           |
| `LEAKAGE_DENY_COLUMNS_V6_BASELINE` |     30 | 치트루트 감사 v6 — 금액 10 · 승인/시점 9 · 시나리오 특화 11      |
| `LEAKAGE_DENY_COLUMNS_V7_DERIVED`  |      7 | 치트루트 감사 v7 — 승인권·한도·한도근접 파생                     |
| **`LEAKAGE_DENY_COLUMNS`(최종)**   | **52** | 위 합집합 — **누적, 해제 없음**                                  |
| `LEAKAGE_DENY_RULES`               |      5 | 룰 단위 차단                                                     |

개수는 본 보고서 작성 시 모듈을 직접 로드해 실측했다. 코드 주석이 정량 근거를 남겼다: 24차원 AUPRC 0.397 → 상위 5개 차단 후 0.056(잔존 14.0%).

**2차: 패턴 기반 차단**(`phase2_plan.py`) — label, target, fraud, anomaly, risk, rule, score, model, prediction, probability, export, dashboard 12토큰과 단계 출력 접두어를 정규식으로 막는다. 트레이드오프도 기록돼 있다 — "priority 같은 넓은 토큰을 추가하면 payment_priority 등 정상 ERP 필드까지 막힌다".

**3차: 물리적 제거**(`schema_validator.py`) — 8개 컬럼을 아예 DataFrame에서 **drop**한다. "신규 룰이 실수로 참조해도 즉시 실패하게" 만드는 것이 목적이며, 테스트가 AST 수준으로 탐지 코드의 참조 여부까지 회귀 검사한다.

**금액 컬럼은 전량 차단**돼 있다. 사유는 "합성 금액이 너무 깨끗해 지름길 학습을 유발"이다.

### 차단이 평가를 막은 지점 (2026-07-25)

3중 방어의 부작용이 예상 밖에서 드러났다. 화면에 ROC 곡선을 붙이려 했더니 부정 데이터셋을 넣어도 **정답 라벨이 없었다** — 실측으로 `general_ledger` 238,672행의 `is_fraud`가 전부 NULL이었다. 라벨 컬럼을 초입에서 물리 제거하는 정책이 학습만이 아니라 **DB 적재까지 막고 있었기** 때문이다. DB 스키마에는 컬럼이 늘 존재하므로 "컬럼이 있다"로 판정하면 라벨이 있는 줄 알고 전부 정상으로 읽는다.

해소는 정책을 완화하는 방향이 아니었다. ROC는 평가 전용 지표이므로 **원본 DataSynth CSV의 문서 단위 라벨만 따로 읽는 해소기**를 두고, 그 값이 피처·점수 경로로 나가지 않게 함수 안에 가뒀다(`dashboard/components/phase2_roc_truth.py`). 학습 경로는 한 줄도 바꾸지 않았다.

여기서 얻은 규칙 하나. **고정 스키마 컬럼은 "존재"가 아니라 "값이 있는가"로 판정한다.** 그리고 라벨을 요구하는 평가 지표는 라벨을 제거하는 정책과 공존해야 하므로, 학습 경로가 아닌 **평가 경로에서 원본을 따로 읽는다.**

## 9.4 평가 설계의 방어 장치

| 장치               | 내용                                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| 행 단위 KFold 금지 | 같은 전표의 행이 학습·평가에 나뉘어 들어가는 것을 원천 차단                                                 |
| 분할 누출 게이트   | 무작위 분할과 그룹 분할의 AUC 차이 > 0.05면 사용자 수준 누출 확정, 그룹-시간 차이 > 0.03이면 시간 누출 확정 |
| 순환 라벨 차단     | 라벨 출처가 탐지 점수나 의사 라벨이면 **강제 부적격**                                                       |
| 저신호 폴백        | 양성 50건 미만 또는 비율 1% 미만이면 학습 중단                                                              |
| 승격 게이트        | 9단계(완료 상태·심각 경고 없음·최소 시행·탐색 다양성·실패율 0.5 이하·지표 하한 등)                          |
| 추론 독립성        | PHASE1의 케이스 우선순위·룰 발화는 ML **입력도 게이트도 아니다**. PHASE1은 추론 *후* 덧붙이기에만 사용      |

마지막 항목이 3-surface 비병합의 코드 수준 구현이다. VAE가 PHASE1 결과를 보고 점수를 매기면 두 표면이 독립이 아니게 된다.

## 9.5 학습 구성과 1차 관문 통과

정상 base에서 학습하고, 미학습 정상 구간의 플래그율이 오염 설정 근처인지 먼저 확인했다.

| 항목                     | 값                           |
| ------------------------ | ---------------------------- |
| 학습 표본                | 50,000행 (라벨 미사용)       |
| 보정 표본                | 50,000행                     |
| 피처 수                  | **71**                       |
| 은닉 차원 / 잠재 차원    | 64 / 32                      |
| epoch / batch / 학습률   | 50 / 256(196배치) / 0.001    |
| beta                     | 1.0                          |
| 재구성 손실 / KL 손실    | 0.2300 / 0.3718 (비율 1.616) |
| 임계                     | 0.9900                       |
| 학습 소요                | 460.9초                      |
| 학습 구간 플래그율       | 0.998%                       |
| **미학습 정상 플래그율** | **1.056%**                   |
| 오염 설정                | 1.00%                        |

사전 선언 대역 [0.3배, 3배] 안이므로 **PASS**다. 모델이 정상을 정상으로 보고 있다는 뜻이다.

부수적으로 제품 버그도 하나 잡았다. 결측이 있는 불리언 피처가 전처리 통과 경로에서 numpy 변환에 실패해 터졌다. 불리언 전용 변환기를 신설해 결측을 부동소수 NaN으로 바꾼 뒤 최빈값으로 대치하도록 고쳤다(수치형이 중앙값 대치를 쓰는 것과 같은 결).

## 9.6 2차 관문 — 부정 데이터에서 무작위 수준

부정 overlay 4벌의 전 행을 채점하고 문서 단위로 평가했다.

| 지표 (시드 4벌 합산)                                       | 값                        |
| ---------------------------------------------------------- | ------------------------- |
| 문서 AUROC 평균                                            | **0.5187** (무작위 ≈ 0.5) |
| recall@top1% 평균                                          | **0.0038**                |
| PHASE1이 표면화하지 못한 부정 중 VAE 상위 1%가 회수한 건수 | **4벌 합계 2건**          |

이후 대시보드에 ROC를 붙이며 같은 계열의 단일 배치(`..._r1` FY2022)를 따로 측정했다.

| 지표                        | 값                            |
| --------------------------- | ----------------------------- |
| 평가 전표 / 부정 전표       | 3,368 / 47 (1.4%)             |
| 문서 AUC                    | **0.6599**                    |
| 부트스트랩 95% CI (2,000회) | **[0.579, 0.733]** — 폭 0.154 |

두 수치 모두 **완화 없이 그대로 적는다.** 0.66은 신뢰구간 폭이 0.154라 소수점까지 신뢰할 값이 아니며, 이는 부정 47건의 직접적 귀결이다. 그리고 다음 절이 밝히듯 두 수치 중 어느 것도 성능 증거가 아니다 — 높아서가 아니라 **측정 대상 데이터가 무효**라서다.

## 9.7 측정이 성립하지 않은 이유 — 데이터에 지름길이 실재했다

원인 후보를 가르려고(EDA 부족·전처리 부족·라벨 부족·튜닝 부족) 개발셋 `..._r1_seed1`에서 먼저 단변량 분리도를 측정했다. 여기서 예상과 다른 것이 나왔다.

| 측정                         | 결과                                                |
| ---------------------------- | --------------------------------------------------- |
| 대상                         | seed1 FY2022, 119,336행 / 37,978전표 / 부정 83전표  |
| 최대 단변량 AUC              | **0.858** (`approved_by` 존재 여부에서 파생된 3종)  |
| 전표 단위 `approved_by` 존재 | 부정 **83/83 = 100%** vs 정상 10,773/37,895 = 28.4% |
| 결측률 차 5%p 초과 컬럼      | 69개 중 **16개**                                    |

**부정 전표가 생성 경로 차이로 특정 컬럼이 통째로 비거나 통째로 차 있었다.** 결측 여부 하나만 점수로 써서 부정을 얼마나 가려낼 수 있는지 재 보면 이렇게 나온다(0.5가 정보 없음, 0이나 1에 붙을수록 결측 패턴이 라벨을 그대로 말해준다).

| 컬럼                      | 결측률(부정) | 결측률(정상) | 결측만으로 AUC | 학습 입력 결정    |
| ------------------------- | -----------: | -----------: | -------------: | ----------------- |
| `is_suspense_account`     |     **100%** |       **0%** |      **1.000** | **exclude**       |
| `batch_id` / `job_id`     |         100% |        23.8% |          0.881 | 결정 기록 없음    |
| `approved_by`             |       **0%** |        72.1% | 0.139 (역방향) | **include**       |
| `debit_account_subtype`   |         100% |        48.4% |          0.758 | 결정 기록 없음    |
| `credit_account_subtype`  |         100% |        51.7% |          0.742 | 결정 기록 없음    |
| `approval_date`           |         100% |        72.1% |          0.639 | exclude           |
| `trading_partner`         |           0% |        17.0% |          0.415 | **include**       |
| `cost_center`             |        70.5% |        60.2% |          0.551 | **include**       |
| `tax_code` / `tax_amount` |        68.7% |        76.4% |          0.461 | include / exclude |

학습 입력 결정은 이 배치의 학습 리포트에서 직접 읽었다(`preprocessing_plan.decisions` **94건 — exclude 56 / include 38**). 두 가지를 정확히 해 둔다.

- **"결정 기록 없음"은 "안전하게 차단됨"이 아니다.** 컬럼 결정 94건 목록에 그 이름이 없다는 사실만 확인했다. 피처 생성 단계에서 다른 컬럼으로 흡수됐는지, 파이프라인이 일찍 떨어뜨렸는지는 미확인이다.
- **홀드아웃에서도 같다.** `..._r1`에 같은 스캔을 돌리면 14개 컬럼이 걸리고 `is_suspense_account` 결측 단독 AUC는 **1.000**으로 동일하다. seed 특유의 사고가 아니라 **생성기의 성질**이다.

### 왜 도메인이 아니라 생성 아티팩트인가

`approved_by`를 예로 든다. 부정 전표는 83/83 = 100%가 승인자를 갖고 정상은 28.4%만 갖는다. 그리고 fraud_type 9종(circular_trading·fictitious_revenue·embezzlement_cash·payroll_ghost_employee 등)이 **전부 예외 없이 100%**다.

현실에서 부정이 승인을 100% 통과하지는 않는다 — 오히려 승인 우회·자기승인이 부정의 특징이고, 이 프로젝트의 룰 어휘도 그 전제로 짜였다([7장](7_PHASE1-1_COMBO-BUILDER.md) 특징 축). 그리고 서로 다른 9개 시나리오가 한 값으로 수렴하는 것은 시나리오 고유의 성질이 아니라 **그 시나리오들을 찍어내는 공통 코드 경로**의 성질이다.

이는 이 프로젝트가 명문화한 DataSynth 규칙의 정면 위반이다 — "데이터 품질(MCAR·typo·format)은 정상/비정상 무관하게 **동일 비율** 적용. ML 지름길 학습·일반화 실패·허위 피처 중요도·합성 아티팩트 방지."

### 게이트가 왜 통과시켰나 — 거짓 PASS가 아니라 좁은 분모

지름길 게이트 16종은 대표본·seed1에서 ALL PASS였다. 게이트 코드를 열어 원인을 확인했다.

| 축                | 분모                                                                                   | 이 결함을 잡지 못한 이유                                                  |
| ----------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| S1 메타 결측률 차 | 메타 컬럼 **8개**(`user_persona`·`cost_center`·`line_text`·`header_text` 등), 임계 8%p | 위 표의 컬럼 대부분이 이 8개에 없다                                       |
| S2 단일피처 분리  | 31컬럼 × (각 값 + `IS NULL`), 정밀도·recall 기준                                       | "채워져 있으면 부정"이라는 **`IS NOT NULL` 쪽 집중은 판정 형태가 아니다** |

`is_suspense_account`·`batch_id`·`job_id`·`debit/credit_account_subtype`·`approval_date`는 두 분모 어디에도 없다. `approved_by`는 S2 분모에 있지만 S2가 보는 형태(값별 정밀도, `IS NULL`의 정밀도)로는 "부정이 100% 채워져 있다"가 걸리지 않는다.

**게이트가 거짓 PASS를 낸 것이 아니라 선언한 범위를 지켰고 그 범위가 좁았다.** [4장](4_DATASYNTH-QUALITY.md) §4.2가 "현실성 카탈로그 146축 중 게이트 구현 49개(34%)"라고 적어 둔 한계의 구체적 대가이며, 그 절이 함께 적은 전략("룰이 읽지 않는 축의 비현실은 결과에 영향 없다")이 **ML에는 적용되지 않는다**는 것이 이번에 드러난 사실이다. 룰은 컬럼을 골라 읽지만 ML은 주어진 컬럼을 다 본다.

## 9.8 역설 — 낮은 수치는 방어가 작동했다는 신호였다

지름길이 실재했다면 점수는 부풀어야 했다. 부풀지 않았다. 홀드아웃(`..._r1`, 3,368전표 / 부정 47)에서 세 숫자를 나란히 놓으면 순서가 뒤집혀 있다.

| 점수                                                 |        AUC |
| ---------------------------------------------------- | ---------: |
| `is_suspense_account` 결측 여부 (**차단된** 지름길)  |  **1.000** |
| `approved_by` 유무 단독 (**통과한** 지름길, include) | **0.7928** |
| VAE 전표 점수 (include 38컬럼 학습)                  | **0.6599** |

> 여기의 "38컬럼"은 이 배치(`fraud_test` / FY2022) 학습 리포트의 컬럼 결정 94건 중 include 수이며, 9.5절의 "피처 71"은 정상 base 학습 실행의 확장 후 피처 수다. 세는 단위(원본 컬럼 vs 인코딩 확장 피처)와 실행이 다른 값이므로 두 숫자를 비교하면 안 된다.

컬럼 하나의 결측 여부가 모델 전체보다 잘 맞춘다. 그리고 학습 입력에 실제로 들어간 지름길(`approved_by`)조차 점수가 따라가지 않았다.

| 측정                               | 값                          |
| ---------------------------------- | --------------------------- |
| VAE 점수 ↔ `approved_by` 유무 상관 | **-0.0493** (사실상 무상관) |
| 승인자 있는 전표의 VAE 점수 평균   | 0.97695                     |
| 승인자 없는 전표의 VAE 점수 평균   | 0.97829                     |

두 군의 평균 차이는 0.0013이다. 이유는 둘이다.

- **가장 강한 지름길은 deny 목록이 입력 전에 잘라냈다.** `is_suspense_account`는 `LEAKAGE_DENY_COLUMNS`에 명시돼 있고 이 배치의 학습 결정도 `exclude`였다. 9.3절의 1차 방어가 설계대로 작동했다.
- **통과한 지름길도 비지도 구조가 성능으로 환산하지 못했다.** VAE는 라벨을 보지 않으므로 "어느 방향이 부정인가"를 모른다. 정상 분포를 재구성하도록만 학습하니, 라벨과 상관된 컬럼이 입력에 있어도 그것을 부정 판별에 동원할 방법이 없다.

같은 데이터로 **지도학습**을 돌렸다면 `approved_by` 하나로 AUC 0.79, deny가 없었다면 `is_suspense_account`로 1.0에 근접한 수치가 나왔을 것이다. 그 수치는 전부 자문자답이다 — 구세대 데이터의 AUROC 0.93이 "흔적을 심고 자기가 심은 것을 찾은" 값으로 무효화된 경로가 정확히 그것이다.

**따라서 0.66과 0.5187은 "성능이 낮다"로 읽을 값이 아니라 "오염된 데이터에서 점수가 부풀지 않았다"로 읽을 값이다.**

여기서 선을 분명히 그어야 한다. 이 절은 **방어 장치가 작동했다는 주장**이고, **모델이 쓸 만하다는 주장이 아니다.** 낮은 수치를 근거로 성능을 옹호하는 것은 나쁜 숫자를 세탁하는 것이며, 이 프로젝트가 AUROC 0.93을 스스로 폐기한 이유와 정확히 반대되는 행동이다. VAE의 부정 탐지 성능은 **여전히 증명되지 않았고, 이 데이터로는 증명할 수도 반증할 수도 없다.**

## 9.9 판정 정정 — 무엇이 바뀌고 무엇이 남았나

| 항목             | 이전 판                                 | 현재                                                             |
| ---------------- | --------------------------------------- | ---------------------------------------------------------------- |
| 측정 수치        | 문서 AUROC 0.5187 / recall@top1% 0.0038 | **그대로** (+ 단일 배치 0.6599, CI [0.579, 0.733] 추가)          |
| 판정 이름        | 행 단위 VAE **검증 실패**               | 행 단위 VAE **성능 검증 불성립 — 측정 데이터 무효**              |
| 낮은 수치의 해석 | 모델이 못 잡았다                        | 오염된 데이터에서 **점수가 부풀지 않았다**(방어 작동)            |
| 원인 설명        | 완전 위장 → 행 단위에 **정보 부재**     | 정보는 있었고 **그 정보가 감사 신호가 아니라 생성 아티팩트**였다 |
| VAE 성능 주장    | 하지 않음                               | **하지 않음 (불변)**                                             |
| 표면의 역할      | 보조 — 정상 밖 비정형 후보 제시         | **불변**                                                         |

### 실패는 사라지지 않고 옮겨갔다

라벨을 고쳐도 실패 항목은 줄지 않는다. 위치가 바뀐다.

- **여전한 실패**: 합성데이터 경로로 비지도 탐지 성능을 증명하려는 시도. 딜레마가 이번에 3분기로 늘었다.

```
    흔적을 심는다      ──▶ 자기가 심은 것을 자기가 찾음 (자문자답)   ↓ 성능 증거 아님
    흔적을 안 심는다    ──▶ 정보가 없어 못 잡음                      ↓ 성능 증거 아님
    안 심으려 했는데
    게이트 밖에서 남았다 ──▶ 측정 자체가 무효 (본 실측)              ↓ 성능 증거 아님
```

- **새로 드러난 실패**: DataSynth 규칙 위반(부정·정상 결측 패턴 불일치)을 **게이트 3겹이 전부 통과시켰다.** 1겹 게이트 57종은 분모에 없었고, 2겹 룰 발화율은 룰이 읽지 않는 컬럼이라 신호를 남기지 않았고, 3겹 지름길 게이트는 결측률 축의 분모가 8컬럼이었다. 이것이 이번 라운드의 실질적 실패이며 조치 대상이다.

- **PHASE1 쪽으로도 번졌다**: 승인 데이터 유무는 VAE 입력이기만 한 것이 아니라 **여러 룰의 판정 입력**이다. 층화 검사에서 승인 의존 룰의 부정·정상 대비가 사라지거나 역전됨을 확인했고, 특히 **L1-07 승인 생략은 부정 표면화가 0.000**이었다(부정이 100% 승인자를 가지므로 발화 불가). 표면 커버리지 자체는 승인 축 밖 룰이 이끌어 방향이 유지되지만, 밀도·대비 수치는 상한으로 격하했다([7.8](7_PHASE1-1_COMBO-BUILDER.md)).

- **취소되지 않는 것**: 이전 라운드가 이 수치를 실패로 **기록해 둔 행위**는 옳았다. 라벨이 부정확했을 뿐 수치를 숨기지 않았고, 그래서 이번에 그 수치를 다시 들여다볼 수 있었다.

### 결정 — 고치지 않고 데이터셋에 부적격 딱지를 붙인다 (2026-07-25)

가장 자연스러운 다음 행동은 생성기를 고쳐 결측 패턴을 동일화하고 다시 재는 것이다. **그렇게 하지 않기로 결정했다.** 근거가 셋이다.

| 근거                        | 내용                                                                                                                                        |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 고쳐서 지킬 것이 없다       | 이 보고서 본문의 검증 수치(발화율 대역·룰 단위시험·빌더 판정·표면 커버리지)는 **다른 데이터셋** 기반이라 이 결함의 영향권 밖이다            |
| 이 데이터셋엔 판별력이 없다 | any-rule 축에서 부정 95.2% vs **정상 98.9%** — 룰이 거의 전 전표에 발화하므로 이 데이터로는 VAE든 룰이든 대비를 만들 수 없다                |
| 고쳐서 얻는 것이 주장 불가  | 산출물은 "더 그럴듯한 합성 수치" 하나인데, 그 수치는 합성 라벨의 자기참조 딜레마 때문에 **애초에 성능 주장에 쓸 수 없다**(9.9절 3분기 도식) |

즉 수정 비용은 Rust 생성기 재작업 + 2.5GB 재생성 + 게이트 재정비인데, 얻는 것은 인용할 수 없는 숫자다. **그래서 여기서 멈춘다.**

대신 딱지를 붙인다. 이 데이터셋은 **성능 측정 부적격(not fit for performance measurement)**이며, [4장](4_DATASYNTH-QUALITY.md) §4.7 데이터셋 표에도 같은 표기를 달았다. 목적은 하나다 — 나중에 누가(작성자 자신을 포함해) **0.660이나 0.5187을 성능으로 인용하지 않게** 하는 것. 이 데이터셋의 정당한 용도는 배선·계약·회귀 확인이고, 성능 수치는 아니다.

미조치로 남기는 것도 명시한다. 둘 다 고치지 않았고, 고칠 계획도 없다.

| 남은 결함                   | 상태                                                                                                      |
| --------------------------- | --------------------------------------------------------------------------------------------------------- |
| 생성기 결측 패턴 불일치     | **미조치** — 위 결정. 재생성 시 함께 다루면 될 항목으로 기록만 남긴다                                     |
| 지름길 게이트 S1 분모 8컬럼 | **미조치** — 전 컬럼으로 넓히고 `IS NOT NULL` 쪽 집중을 판정에 넣어야 같은 결함을 잡는다. 설계만 기록한다 |

측정 재현 절차와 회차별 원본 기록은 `dev/active/phase2-vae-auc-diagnosis/`에 있다 — 진단 문서 2건(`PHASE2_VAE_DATASET_INVALIDITY.md`, `plan.md`), 재현 스크립트 3종(`measure_separability.py`·`scan_shortcuts.py`·`measure_rule_contamination.py`), 산출 CSV·JSON 7건. 실행 명령은 [13장](13_TEST-DECISIONS.md) §13.6에 정리했다.

## 9.10 이 라운드가 남긴 것

**표면의 역할은 그대로다.** VAE는 "학습된 정상 밖 비정형의 추가 검토 후보 제시"라는 보조 역할로만 유지하며, **부정 탐지 성능을 주장하는 표면으로 쓰지 않는다.** 판정 라벨이 "실패"에서 "불성립"으로 바뀌어도 이 결론은 움직이지 않는다 — 성능이 증명되지 않았다는 사실이 같기 때문이다.

**업계 실무와의 정합성을 확인했다.** 빅4 도구를 조사한 결과는 이렇다.

| 도구           | 방식                      |
| -------------- | ------------------------- |
| EY Helix GLAD  | 감사인 라벨 기반 지도학습 |
| KPMG Clara     | 룰·기준 분석 위에 ML 보조 |
| PwC Halo       | 룰 묶음 + 의심 점수       |
| Deloitte Omnia | 기준 기반 분석            |

네 도구 모두 룰·기준이 주력이고 ML은 보조이며, **비지도 딥러닝 단독 탐지는 실무에 없다.** 본 프로젝트의 구조(결정론 룰이 주 표면, VAE는 병합하지 않는 보조)는 이 관행 안에 있다.

**측정 인프라는 유지했다.** 평가 방어 장치(그룹 분할 강제, 누출 게이트, 순환 라벨 차단, 컬럼 deny)는 실데이터가 유입되면 그대로 쓸 수 있다. 이번 라운드가 그 인프라의 값어치를 실측으로 보여준 셈이다 — 오염된 데이터가 들어왔을 때 점수를 부풀리지 않은 것이 그 장치들이다.

**실패한 지표를 화면에 그대로 띄웠다.** 2026-07-25에 VAE 탭에 ROC 곡선을 붙였다(AUC·부정 전표·평가 전표·부정 비율 카드 포함). 좋은 숫자가 나오지 않는 지표를 감추는 편이 보기에 낫지만, 이 표면이 무엇을 하는지 감사인이 판단하려면 **얼마나 못 맞히는지가 보여야** 한다. 곡선 옆에 "VAE는 학습에 라벨을 쓰지 않으며 성능 검증에만 사용한다"와 라벨 출처를 함께 적었다. 라벨이 없어 곡선을 그릴 수 없을 때도 "부정 라벨이 없다"·"원본 파일을 못 찾았다"·"`document_id`가 맞물리지 않는다"를 각각 다른 문장으로 구분한다.

> 화면에 뜨는 AUC는 그 배치의 점수 부여 전표만 대상이며, **어느 수치도 성능 근거로 인용하지 않는다**([11장](11_DASHBOARD.md) 11.7). 데이터가 무효인 동안 그 숫자는 배선이 동작한다는 증거일 뿐이다.

## 9.11 실증 예시 — 컬럼 하나가 모델보다 잘 맞히는 순간

`is_suspense_account` 컬럼 하나를 따라가면 이 장의 논지가 한 줄로 보인다.

이 컬럼은 "가계정인가"를 나타내는 불리언이다. 홀드아웃 데이터에서 값을 보지 않고 **비어 있는지만** 확인하면 이렇게 갈린다 — 부정 전표는 100%가 비어 있고 정상 전표는 0%가 비어 있다. 그래서 "비었으면 부정"이라는 한 줄 규칙의 AUC가 **1.000**이다. 완벽한 분류기다.

물론 이것은 감사 신호가 아니다. 가계정 플래그가 비어 있다는 것은 그 전표가 부정이라는 뜻이 아니라, **그 전표를 만든 코드 경로가 이 필드를 채우지 않았다**는 뜻이다. 부정 overlay를 얹는 생성 경로가 정상 base 경로와 달랐고, 그 차이가 컬럼의 빈칸으로 남았다. 감사인에게 "가계정 칸이 비었으니 부정입니다"라고 말할 수는 없다.

이 컬럼은 **VAE 입력에 들어가지 않았다.** `LEAKAGE_DENY_COLUMNS`에 명시돼 있고 이 배치의 학습 결정도 `exclude`였다. 치트루트 감사(2026년 상반기)에서 단일 컬럼 AUROC 0.95 이상으로 걸러 deny에 넣어 둔 것이 이번에도 같은 일을 막았다. 만약 들어갔다면, 그리고 지도학습을 돌렸다면 AUC는 1.0 근처가 나왔을 것이고 그 숫자는 **"우리가 파일을 안 채운 것을 우리 모델이 찾아낸" 값**이었을 것이다.

같은 데이터에서 통과한 지름길도 있다. `approved_by`는 include로 학습에 들어갔고 단독 AUC가 0.7928인데, VAE 점수와의 상관은 -0.0493이다. 비지도 모델은 "승인자가 있는 쪽이 부정"이라는 방향을 알 방법이 없어서 그 정보를 쓰지 못했다.

세 숫자의 순서 — 차단된 지름길 1.000 > 통과한 지름길 0.793 > 모델 0.660 — 가 이 장의 요약이다. **첫 줄은 방어가 막았고, 둘째 줄은 구조가 환산하지 못했고, 셋째 줄은 그래서 아무것도 증명하지 못한다.** 세 줄 중 어느 것도 "모델이 부정을 알아봤다"가 아니다.

그리고 같은 전표를 **PHASE1 룰은 잡는다.** 비용자산화 룰은 "비용 성격 지출이 자산 계정에 기표됐다"는 계정 간 **관계**를 보기 때문이다. 그 관계는 컬럼이 채워졌는지 비었는지와 무관하며, 생성 경로가 바뀌어도 남는다. 이것이 결정론 룰을 주 표면으로 두는 이유다 — 룰은 **무엇을 보는지 선언하고 그것만 본다.**

## 9.12 실세계는 이것을 어떻게 하나

행 단위 비지도 탐지가 여기까지 온 것을 "데이터가 부족했다" 또는 "튜닝이 모자랐다"로 읽으면 오독이다. 실세계 금융 이상탐지의 작동 방식과 대조하면 이 표면의 위치가 드러난다.

핵심 사실: **실무는 원시 전표 한 줄을 모델에 넣지 않는다.** 신호는 원시 행이 아니라 가공한 피처와 맥락에 있다.

| 도메인             | ML/DL이 되는가  | 이유                                                                                                         |
| ------------------ | --------------- | ------------------------------------------------------------------------------------------------------------ |
| 신용카드 부정      | **잘 된다**     | "카드 30일 평균 대비 금액", "직전 거래와의 거리·시간", 가맹점 위험도 등 **행동·속도 피처** + **대량 실라벨** |
| 자금세탁(AML)      | 보조적          | **규칙 + 관계망(그래프) + 사람 리뷰**가 주력. 라벨 희소·불확실, ML은 랭킹 보조                               |
| 재무제표·전표 부정 | **가장 어렵다** | 부정이 정상처럼 위장돼 원시 행엔 신호가 적고, 집계 분석·교차대사·원장 밖 맥락에서 신호가 나온다              |

신용카드가 되는 이유는 딥러닝이 마법이어서가 아니라, **신호를 담은 행동·속도 피처를 사람이 설계**하고 **막대한 실제 라벨**로 지도학습하기 때문이다. 전표 부정에는 그 세 조건(가공 피처·실라벨·원시 행 신호)이 모두 약하다.

그리고 이 프로젝트는 [1장](1_OVERVIEW.md)에서 **단일 법인 원장으로 스코프를 확정하며 거래처 마스터·은행·관계망·외부 대사를 데이터에서 제외**했다. 실무 부정탐지가 기대는 관계·집계·외부 신호가 데이터에 **원리적으로 부재**하도록 스스로 선을 그은 것이다(그 선은 감사 계약이 법인 단위라는 현실에 근거한 옳은 결정이었다). 여기에 합성 라벨의 딜레마(9.9절)가 겹친다.

따라서 조건이 곱해진다: **가장 어려운 도메인 × 업계도 안 쓰는 방법(원시 행 비지도) × 신호가 사는 데이터를 스코프에서 제외 × 측정에 쓸 합성 라벨의 자기참조.** 이 곱 위에서 성능을 증명하려던 시도가 성립하지 않은 것이고, 데이터를 고쳐 재측정한다 해도 앞의 세 조건은 그대로 남는다.

역으로, 업계가 실제로 쓰는 방식 — **도메인 지식을 규칙으로 명시하고 그 위에 검토 우선순위를 세우는 것** — 은 이 프로젝트의 [PHASE1 룰 엔진](6_PHASE1-1_RULES.md)과 [조합 빌더](7_PHASE1-1_COMBO-BUILDER.md)가 이미 구현한 것이다. 즉 "되는 쪽"은 만들었고, "안 되는 쪽"은 왜 안 되는지를 측정으로 규명해 기록했다. 후자를 "된다"고 포장하지 않은 것, 그리고 낮은 수치가 유리하게 재해석될 수 있는 국면에서도 **성능 주장으로 바꾸지 않은 것**이 이 장의 규율이다.
