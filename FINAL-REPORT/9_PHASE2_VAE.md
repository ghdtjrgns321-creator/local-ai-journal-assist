# 9. PHASE2 — 비지도 VAE와 판정이 네 번 고쳐진 기록

## 9.1 파이프라인 내 위치

```
                              ┌─ PHASE1-1 룰
검증 통과 DataFrame ──────────┼─ PHASE1-2 분석신호
                              └─ ▶▶▶ [PHASE2 VAE — 별도 실행·별도 표시] ◀◀◀
```

정상 데이터만으로 "정상의 모양"을 학습한 뒤, 복원이 잘 안 되는 행을 추가 검토 후보로 올리는 표면이다.

### 현재 판정 — 폐기 조건 불성립, 표면 유지

입력을 재설계하고 학습 시드를 고정한 **회차 C(2026-07-29)** 의 실측이다.

| 항목                      | 값                                               |
| ------------------------- | ------------------------------------------------ |
| 문서 AUROC (4벌 평균)     | **0.8845** (폭 0.0154, `torch.manual_seed` 고정) |
| recall@top1% (4벌 평균)   | 0.3568                                           |
| 반응하는 수법             | **가공매출 계열에 몰림** (FS01 · FS05)           |
| 반응하지 않는 수법        | 유령급여·FS08·FS12·FS13 — 4벌 내내 거의 **0건**  |
| 상보성(룰이 놓친 것 회수) | **측정 불가** — 전체 룰 기준 미표면이 0~2건      |

**"룰이 놓친 것을 VAE가 회수한다"는 주장은 하지 않는다.** 룰이 330건 중 328~330건을 목록에 올리므로 놓친 것 자체가 0~2건이고, 보완을 잴 대상이 없다. 2026-07-29 판에는 무정보 룰을 뺀 분모로 만든 "27/124(21.8%)"가 실려 있었으나 **5차 정정(2026-08-01)에서 철회했다**([9.6](#상보성-지표는-철회한다-5차-정정-2026-08-01)).

남는 진술은 둘이다 — 판별력은 무작위(0.5)보다 뚜렷이 높고, 반응 범위는 가공매출 계열에 몰린다. 상세는 [9.6](#96-2차-관문--학습-표본에-따라-결과가-뒤집혔다)·[9.6.1](#961-무엇을-보고-올렸나--기여-분해).

### 판정은 다섯 차례 고쳐졌다

| 정정 | 시점       | 판정 이름                           | 무엇이 바뀌었나                                     |
| ---- | ---------- | ----------------------------------- | --------------------------------------------------- |
| 최초 | 2026-07-18 | 검증 실패                           | AUROC 0.5187을 모델의 실패 수치로 기록              |
| 1차  | 2026-07-25 | 성능 검증 불성립 — 측정 데이터 무효 | 정보는 있었고 그것이 **생성 아티팩트**였다          |
| 2차  | 2026-07-26 | 불변                                | 낮은 수치는 방어 성과가 아니라 **학습 부족**이었다  |
| 3차  | 2026-07-27 | 불변                                | "생성기를 고치지 않는다"는 **결정 자체**를 뒤집었다 |
| 4차  | 2026-07-29 | 폐기 조건 불성립 — 표면 유지        | 입력 배관을 고치고 재측정 → 0.8845, 재현됨          |
| 5차  | 2026-08-01 | **표면 유지, 단 상보성 주장 철회**  | 27/124는 분모를 사후에 바꿔 만든 값이라 인용 중단   |

아래 절들은 이 과정을 시간순으로 남긴다. **회차 A·B의 수치(0.5187 · 1.0000 · 0.66)와 그때의 해석은 전부 이력이며 인용하지 않는다** — 시드가 고정되지 않았고 입력 구성이 달랐으므로 회차 C와 비교할 수도 없다. 정정 이력은 9.9절에 표로 정리돼 있다.

## 9.2 왜 비지도인가

합성데이터에서 지도학습은 순환 논증이다. 부정 라벨은 우리가 규칙으로 심은 것이므로 모델이 학습하는 것은 부정이 아니라 **우리의 주입 규칙**이다. 치트루트 감사가 이를 수치로 확인했다([4장](4_DATASYNTH-QUALITY.md)) — 단일 컬럼만으로 AUROC 0.95 이상이 18건, 시뮬레이션 로지스틱 평균 0.9978.

비지도는 라벨을 쓰지 않으므로 이 함정을 피한다. 정상 분포만 학습하고 그 밖을 표시하는 방식이라 합성데이터에서도 유효할 것으로 봤다. **이 기대는 세 라운드 동안 검증되지 않았고, 네 번째에 좁은 범위에서만 확인됐다** — 회차 C에서 가공매출 계열은 회수하고 다른 네 수법은 한 건도 회수하지 못했다([9.6](#96-2차-관문--학습-표본에-따라-결과가-뒤집혔다)).

한 가지는 분명히 해 둔다. 라벨을 쓰지 않는 성질이 **오염된 데이터에서 점수를 부풀지 않게 막아 주지는 않았다.** 한때 그렇게 읽었으나 2026-07-26에 반증됐다 — 차단 설정을 그대로 두고 학습 표본만 늘리자 모델이 통과한 아티팩트를 조합해 썼다([9.8](#98-낮은-수치를-어떻게-읽었고-그-읽기가-왜-틀렸나)).

## 9.3 입력 경계 — 허용 목록과 3중 방어

### 9.3.0 무엇이 들어오는가는 허용 목록이 정한다 (2026-07-29 전환)

그전까지 PHASE2 입력은 **막지 않은 것이 전부 들어오는** 구조였다. PHASE1 이 룰을 위해 칸을 하나 만들면 그 순간 PHASE2 입력이 하나 늘었다 — 아무도 결정하지 않았는데.

```
  raw 원장 ─▶ [PHASE1 피처 엔진] ─▶ featured(원본 59 + 룰용 파생 39)
                                        │
                        ┌───────────────┴───────────────┐
                        ▼                               ▼
                   PHASE1 룰                    PHASE2 입력 ← deny 에 안 걸린 전부
```

그렇게 흘러든 PHASE1 파생이 **39칸**이었고, 그중 한도·승인 축 18칸이 원재료 3개에서 나온 것이었다. `near_threshold_amount` 와 `document_approval_amount` 는 코드상 같은 변수를 두 이름으로 저장한 것이었고(`amount_features.py:303, 426`), `description_both_missing` 은 정의상 `line_missing & header_missing` 이었다(`text_features.py:278`).

룰에게는 합리적인 칸들이다 — L2-01 은 "한도의 몇 %인가"가 발화 조건이니 비율 칸이 필요하다. **VAE 에게는 아니다.** 금액과 한도 두 칸을 주면 관계는 스스로 학습하고, 파생을 더 주면 정보가 아니라 그 축의 무게만 는다.

그래서 방향을 뒤집었다. **PHASE2 입력은 `preprocessing/phase2_features.py` 에 적힌 것만이다.**

```
  raw 원장 ─┬─▶ [PHASE1 피처 엔진] ─▶ featured ─▶ PHASE1 룰
            │
            └─▶ [PHASE2 입력 빌더] ─▶ 허용 원본 39 + 전용 파생 12 ─▶ PHASE2
                      │
                 원본으로 표현 못 하는 것만 파생
```

파생은 세 종류로 제한한다.

| 종류        | 왜 원본으로 안 되나                                  | 칸                                   |
| ----------- | ---------------------------------------------------- | ------------------------------------ |
| 날짜        | datetime 은 크기 비교가 무의미(12월과 1월이 가장 멂) | 요일·시각·월중일자·공휴일 · 간격 3종 |
| 마스터 조인 | 원장에 없는 정보                                     | 승인자 한도 · 명단 등재              |
| 금액 구조   | 로그 변환에서 소실됨                                 | 끝자리 0 개수 · 첫자리               |

판정(`is_near_threshold`)·비율(`gap_ratio`)·중복 표현(`amount_magnitude`)은 만들지 않는다. **입력 98칸 → 51칸.**

이 전환의 요점은 칸 수가 아니다. **3-surface 비병합([9.4](#94-평가-설계의-방어-장치))이 점수만이 아니라 입력에서도 성립하게 된 것**이다. 그전까지 PHASE2 는 PHASE1 이 룰을 위해 깎아놓은 렌즈로 데이터를 보고 있었다.

### 9.3.1 3중 방어 — 이제 2차 방어다

모델이 답을 훔쳐보지 못하게 막는 장치가 세 겹이다. 허용 목록이 1차 관문이 된 뒤로 **아래 목록은 한 칸도 발동하지 않는다**(실측: 허용 ∩ 차단 = 0). 남기는 이유는 죽은 코드로 두려는 게 아니라 **허용 목록의 가드레일**이기 때문이다 — 누군가 허용 목록에 위험한 칸을 추가하면 `test_allow_list_and_deny_list_never_overlap` 이 즉시 실패한다.

**1차: 컬럼 deny 목록**(`src/preprocessing/constants.py`)

| 상수                                 |   개수 | 근거                                                             |
| ------------------------------------ | -----: | ---------------------------------------------------------------- |
| `LABEL_COLUMNS`                      |      8 | is_fraud, fraud_type, is_anomaly, anomaly_type, sod_violation 등 |
| `SYNTHETIC_ONLY_COLUMNS`             |     18 | 위 8개 + mutation 계열 6, 합성 플래그 2, 시나리오 ID, 탐지 힌트  |
| `LEAKAGE_DENY_COLUMNS_STRUCTURAL`    |     15 | 재측정으로 못 푸는 것 — 정답지·조작메모·식별자·비식별화·기술필드 |
| `LEAKAGE_DENY_COLUMNS_MEASURED`      |      1 | 실측으로 아직 SOFT 대역에 남은 것(§9.3.2)                        |
| `LEAKAGE_DENY_COLUMNS_PHASE1_OUTPUT` |      6 | PHASE1 집계 산출물 — 2026-07-28 신설(§9.4 참조)                  |
| **`LEAKAGE_DENY_COLUMNS`(최종)**     | **22** | 위 합집합                                                        |
| `LEAKAGE_DENY_RULES`                 |      5 | 룰 단위 차단                                                     |

개수는 본 보고서 작성 시 모듈을 직접 로드해 실측했다. 코드 주석이 정량 근거를 남겼다: 24차원 AUPRC 0.397 → 상위 5개 차단 후 0.056(잔존 14.0%).

목록은 **두 갈래로 나뉜다.** 구조적 차단은 데이터가 바뀌어도 유지된다 — 정답지는 실 ERP 에 없고 식별자는 모델에 난수이므로 측정할 사안이 아니다. 실측 차단은 **근거가 데이터에 매여 있으므로 데이터가 바뀌면 다시 재야 한다.** 그 재측정 결과가 §9.3.2다.

### 9.3.2 차단 근거 전수 재검 — 58칸에서 22칸으로 (2026-07-29)

deny 목록은 원래 **누적만 하고 해제하지 않는** 원칙이었다. 그 원칙이 틀렸다는 것이 이번 재검의 결론이다.

근거의 출처는 전부 **치트루트 감사 v6/v7(2026-05)** 이었다. 그런데 그 감사는 **결측 누출과 조합 누출이 살아 있던 생성기**에서 잰 값이다. r9(2026-07-27)에서 도너 복제 구조로 재설계하며 그 누출들을 제거했으나, **차단은 한 번도 재측정하지 않았다.**

```
  v6 데이터 ─▶ [치트루트 감사] ─▶ deny 37칸 ─┐
  (누출 있음)                                  │
                                              ├─▶ deny 58칸 ─▶ PHASE2 입력
  생성기 재설계 ─▶ r9 데이터 ─▶ (재측정 없음) ─┘        │
  (누출 제거)                                          ▼
                                              차대변 금액을 못 봄
```

전수 재측정 결과 — 기준선은 v6 감사가 쓴 것을 그대로 사용했다(HARD AUROC ≥ 0.95 / SOFT 0.80~0.95).

| 컬럼                           | v6 감사 | r9 재측정 | 판정     |
| ------------------------------ | ------: | --------: | -------- |
| `debit_amount` `credit_amount` |   0.917 |  **0.71** | 근거소멸 |
| `local_amount`                 |   0.918 |  **0.78** | 근거소멸 |
| `invoice_amount`               |   0.853 |  **0.56** | 근거소멸 |
| `tax_amount`                   |   0.848 |  **0.57** | 근거소멸 |
| `days_backdated`               |       — |  **0.50** | 근거소멸 |
| `exceeds_threshold`            |       — |  **0.51** | 근거소멸 |
| `near_threshold_gap_ratio`     |       — |  **0.86** | SOFT     |

**HARD 판정 0건.** 차단 중이던 비구조적 29칸 중 26칸이 근거소멸, 1칸이 SOFT, 2칸이 측정불가(결측 98%↑)였다. `days_backdated` 0.50 은 정확히 동전 던지기다 — 아무 정보도 흘리지 않는데 두 달 넘게 막혀 있었다.

해제 결과 원본 CSV 73칸 중 사용이 **28 → 37칸**으로 늘었다. 새로 들어온 것은 금액 6칸(`debit`·`credit`·`local`·`invoice`·`supply`·`tax`)과 `is_intercompany`·`is_suspense_account`·`header_text`다.

원칙도 코드에 박았다 — **deny 목록은 누출 차단 전용이다.** 파생 피처끼리의 중복(금액 계열 다수 등)은 여기서 다루지 않는다. 섞으면 "왜 막혔는지"를 다시 잃는다.

이 재검이 남긴 규칙 하나. **차단은 근거와 함께 만료된다.** 근거가 데이터에 매여 있으면 데이터가 바뀔 때 차단도 다시 재야 하고, 그러지 않으면 원장의 핵심인 차대변 금액을 영구히 못 보는 상태가 "안전"이라는 이름으로 굳는다.

### 9.3.3 금액 해제가 드러낸 스케일 결함 3건

차단을 풀자 그 아래 가려져 있던 결함이 나왔다. 금액이 없을 때는 수치형이 사실상 0칸이라 보이지 않던 것들이다.

| 결함                          | 증상                                     | 원인                                                                |
| ----------------------------- | ---------------------------------------- | ------------------------------------------------------------------- |
| robust 스케일 폭발            | `days_backdated` 변환 후 최대 **8.8e13** | 중앙 50%가 전부 0 → IQR=0 → `max(iqr, 1e-12)` 로 나눔               |
| 고카디널리티 건수 칸 무스케일 | `approved_by__count` std **15,842**      | 원값 그대로 출력. 게다가 `count = freq × 행수` 라 freq 와 동일 정보 |
| 금액 판정 오탐                | `amount_zscore__signed_log`              | 이름에 `amount` 가 있으면 금액으로 봄 — z 점수·자릿수에 로그를 재차 |

첫째는 `max(iqr, std, eps)` 로 하한을 올려 고쳤다. 대칭 분포에서는 IQR(≈1.35σ)이 커서 robust 가 유지되고, 희소하거나 꼬리가 두꺼운 칸에서는 std 가 이겨 출력이 1 근처로 묶인다. 둘째는 `__count` 칸을 폐지했다 — 정보가 같은 칸을 둘 두면 그 축이 재구성 손실을 두 배로 먹는다. 셋째는 `zscore`·`magnitude`·`ratio` 등 파생 지표 토큰을 금액 판정에서 제외했다.

세 지점의 입력 행렬 분산 점유율이다. **분산 점유율은 재구성 손실 지배력의 대리 지표다** — VAE 점수가 칸별 제곱오차의 합이므로, 한 그룹의 분산합이 전체에서 차지하는 몫이 그 그룹의 발언권이 된다.

| 시점             | 최악 편중             |  최대 std | P1 지적 |
| ---------------- | --------------------- | --------: | ------: |
| 이중 변환 시절   | categorical **93.5%** |     1.6e4 |       7 |
| 금액 해제 직후   | numeric **100.0%**    |    2.7e12 |       7 |
| 결함 1·2 수정 후 | amount **45.0%**      | **1.000** |   **0** |
| 결함 3까지 수정  | amount **36.5%**      | **1.000** |   **0** |

최종 분포는 amount 36.5%(12칸) · categorical 34.1%(274칸) · numeric 23.8%(9칸) · boolean 5.6%(22칸), 입력 317칸이다. **std 가 1.0 을 넘는 칸이 없고, 40%를 넘는 그룹도 없다.** 시작점이 한 그룹 93.5%였다.

칸 수와 발언권이 어긋나지 않는 것이 요점이다 — categorical 이 274칸으로 압도적으로 많지만 원-핫 한 칸의 분산이 최대 0.25(p=0.5)라 34.1%에 머문다. 범주 컬럼 하나의 총분산이 `1 - Σp² ≤ 1` 이므로 표준화된 수치형 한 칸과 대등해지는 구조다. 이중 변환 시절에는 이 더미들이 각각 std 1 로 부풀어 93.5%를 먹었다.

남은 편중은 스케일이 아니라 **중복**이다. amount 12칸의 독립 정보는 5개 안팎이다 — `near_threshold_amount` 와 `document_approval_amount` 는 재검에서 AUROC 가 소수점 넷째 자리까지 같았고(행 0.6798 · 문서 0.6652), `approver_limit_amount` 와 `near_threshold_limit_amount` 도 같았다. 같은 값이 다른 이름으로 두 번 들어가 있다는 뜻이다. 중복 축은 deny 목록이 다룰 사안이 아니므로 별도로 처리한다.

**2차: 패턴 기반 차단**(`phase2_plan.py`) — label, target, fraud, anomaly, risk, rule, score, model, prediction, probability, export, dashboard 12토큰과 단계 출력 접두어를 정규식으로 막는다. 트레이드오프도 기록돼 있다 — "priority 같은 넓은 토큰을 추가하면 payment_priority 등 정상 ERP 필드까지 막힌다".

**3차: 물리적 제거**(`schema_validator.py`) — 8개 컬럼을 아예 DataFrame에서 **drop**한다. "신규 룰이 실수로 참조해도 즉시 실패하게" 만드는 것이 목적이며, 테스트가 AST 수준으로 탐지 코드의 참조 여부까지 회귀 검사한다.

**금액 컬럼은 2026-07-29 전수 재검에서 해제됐다**(§9.3.2). 차단 사유였던 "합성 금액이 너무 깨끗해 지름길 학습을 유발"은 v6 데이터 기준이었고, r9 재측정에서 단독 AUROC 0.56~0.78 로 기준선 아래였다.

### 차단이 평가를 막은 지점 (2026-07-25)

3중 방어의 부작용이 예상 밖에서 드러났다. 화면에 ROC 곡선을 붙이려 했더니 부정 데이터셋을 넣어도 **정답 라벨이 없었다** — 실측으로 `general_ledger` 238,672행의 `is_fraud`가 전부 NULL이었다. 라벨 컬럼을 초입에서 물리 제거하는 정책이 학습만이 아니라 **DB 적재까지 막고 있었기** 때문이다. DB 스키마에는 컬럼이 늘 존재하므로 "컬럼이 있다"로 판정하면 라벨이 있는 줄 알고 전부 정상으로 읽는다.

해소는 정책을 완화하는 방향이 아니었다. ROC는 평가 전용 지표이므로 **원본 DataSynth CSV의 문서 단위 라벨만 따로 읽는 해소기**를 두고, 그 값이 피처·점수 경로로 나가지 않게 함수 안에 가뒀다(`dashboard/components/phase2_roc_truth.py`). 학습 경로는 한 줄도 바꾸지 않았다.

여기서 얻은 규칙 하나. **고정 스키마 컬럼은 "존재"가 아니라 "값이 있는가"로 판정한다.** 그리고 라벨을 요구하는 평가 지표는 라벨을 제거하는 정책과 공존해야 하므로, 학습 경로가 아닌 **평가 경로에서 원본을 따로 읽는다.**

### 9.3.4 컬럼별 전처리 — 무엇을 어떻게 넣는가

입력 51칸이 매트릭스에서 어떻게 되는지다. 규칙은 **컬럼이 무엇이냐**로 정하고, 카디널리티 같은 숫자 임계는 역할이 안 정해진 칸의 폴백으로만 쓴다.

| 성격             | 처리                                      | 칸                                                           |
| ---------------- | ----------------------------------------- | ------------------------------------------------------------ |
| 분류·코드        | 원-핫(희소 `__RARE__`·결측 `__MISSING__`) | 계정과목·전표유형·업무프로세스·세무구분·역할·회계연도·회계월 |
| 이름·식별        | 빈도(전체에서 차지하는 비율)              | 승인자·작성자·거래처·부서·보조계정·적요                      |
| 금액             | 부호 유지 로그 → 크기만 나눔              | 차변·대변·원화·송장·공급가·세액·승인자 한도                  |
| 그 밖의 수치     | 치우침을 보고 robust/standard 자동        | 날짜 간격 3종 · 끝자리 0 개수                                |
| 불리언           | 0/1                                       | 증빙·관계사·가계정·공휴일·승인자 명단 등재                   |
| 결측이 정보인 칸 | 위 처리 + `__missing` 표식 1칸            | 세액 · 승인 간격 · 인도 간격 · 승인자 한도                   |

**측정된 균형**: `std` 최대 **1.033**. 어느 칸도 재구성 손실을 지배하지 않는다.

이 절이 존재하는 이유는 각 규칙이 **실패를 겪고 나온 것**이기 때문이다.

**① 이름 칸을 카디널리티로 가르면 회사마다 처리가 뒤집힌다.** 실측 r9 `approved_by` 는 6만 행 표본에서 48종(원-핫 48칸), 전 행에서 60종(빈도 1칸)이었다. 임계 50 을 사이에 두고 인코딩이 통째로 바뀐다 — 승인자가 45명인 회사와 55명인 회사가 다른 전처리를 받는다는 뜻이다. 임계가 답하려던 "칸을 몇 개 쓸까"는 희소 값 묶음이 이미 풀고 있었고, 남은 질문 "무엇을 보게 할까"는 도메인이 답한다. 감사에서 승인자·거래처는 **누가**보다 **얼마나 드문가**가 신호다.

**② 숫자로 저장됐다고 수량인 것은 아니다.** `fiscal_year`(2023·2024)와 `fiscal_period`(1~12)를 수치형으로 표준화하면 "2024가 2022보다 크다", "12월과 1월이 가장 멀다"를 학습한다. 회계에서 12월(결산)과 1월(기초)은 붙어 있고 감사에서 가장 중요한 구간이다.

**③ 결측은 정보다 — 불리언에도 수치형에도.** `p2_days_approval_minus_posting` 은 승인이 없으면 비는데(실측 72%) 0 으로 채우면 "승인 없음"과 "당일 승인"이 같아진다. `p2_approver_limit_amount` 는 "승인 불요"와 "한도 0원"이 같아진다. 규칙은 하나다 — 결측이 있고 값이 실제로 갈리는 칸에 표식을 세운다. 값이 한 종류뿐이면 값 칸 자체가 이미 결측 여부를 담으므로 표식을 붙이지 않는다(같은 정보 2칸 방지).

**④ "90% 넘게 비면 고장난 칸"이 항상 참은 아니다.** `is_cleared`(가계정 정리 여부)는 가계정이 아닌 전표에서 물어볼 수 없는 질문이라 빈다 — 실측 가계정 행 결측 0% / 그 외 100%, 전체 95%. 자동 제외에서 빼고 원-핫으로 넣으면 세 상황이 갈린다.

| 값                        |   건수 | 뜻                           |
| ------------------------- | -----: | ---------------------------- |
| `is_cleared__True`        |  2,809 | 정리된 가계정                |
| `is_cleared__False`       |    135 | **미정리 가계정** (L3-09 축) |
| `is_cleared____MISSING__` | 57,056 | 가계정 아님                  |

**⑤ 이름으로 성격을 판정하면 오탐이 난다.** `amount` 가 들어갔다고 통화 금액이 아니다 — `amount_zscore`(z 점수)·`p2_amount_trailing_zeros`(0 의 개수)에 부호 유지 로그를 씌우면 의미가 깨진다. `label` 이 들어갔다고 정답 라벨이 아니다 — `auxiliary_account_label`(보조계정 명칭, '기업다이렉트(유)')이 잘리고 있었다. 둘 다 토큰 예외로 갈랐고, 판정 어휘가 접두어에 있는 `fraud_label`·`risk_label` 은 그대로 차단된다.

## 9.4 평가 설계의 방어 장치

| 장치               | 내용                                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| 행 단위 KFold 금지 | 같은 전표의 행이 학습·평가에 나뉘어 들어가는 것을 원천 차단                                                 |
| 분할 누출 게이트   | 무작위 분할과 그룹 분할의 AUC 차이 > 0.05면 사용자 수준 누출 확정, 그룹-시간 차이 > 0.03이면 시간 누출 확정 |
| 순환 라벨 차단     | 라벨 출처가 탐지 점수나 의사 라벨이면 **강제 부적격**                                                       |
| 저신호 폴백        | 양성 50건 미만 또는 비율 1% 미만이면 학습 중단                                                              |
| 승격 게이트        | 9단계(완료 상태·심각 경고 없음·최소 시행·탐색 다양성·실패율 0.5 이하·지표 하한 등)                          |
| 추론 독립성        | PHASE1의 케이스 우선순위·룰 발화는 ML **입력도 게이트도 아니다**. PHASE1은 추론 *후* 덧붙이기에만 사용      |

마지막 항목이 3-surface 비병합의 코드 수준 구현이다. VAE가 PHASE1 결과를 보고 점수를 매기면 두 표면이 독립이 아니게 된다.

### 그 마지막 항목은 주장이었고, 코드가 지키지 않았다 (2026-07-28)

부정 overlay 재설계 후 VAE 판별력의 출처를 피처별로 갈라보다가 발견했다. **VAE 입력 71칸 중 6칸이 PHASE1 탐지 산출물이었다** — `anomaly_score` · `risk_level` · `flagged_rules` · `review_rules` · `risk_floor_reasons` · `topside_score`. 게다가 단변량 분리력 1위가 `topside_score`(문서 AUC 0.7066), 3위가 `anomaly_score`(0.6272)였다. 위 표가 "입력이 아니다"라고 선언한 것이 사실은 **가장 강한 입력**이었다.

경로는 파이프라인이 집계 결과를 원본 DataFrame 에 되쓰는 곳이다.

```python
# src/pipeline.py — 룰 집계 직후
for col in agg_df.columns:
    df[col] = agg_df[col].values
```

되쓰기 자체는 대시보드가 전표 표에 점수를 붙이기 위해 필요하다. 문제는 **그 프레임이 PHASE2 입력으로도 흘러간다**는 것이었다. 그래서 경로별로 실태가 갈렸다.

| 경로                    | PHASE2가 받는 프레임       | 판정     |
| ----------------------- | -------------------------- | -------- |
| 신규 실행               | 탐지 **전** 스냅샷         | 정상     |
| 재탐지(`redetect`)      | 탐지 **후** 스냅샷         | **오염** |
| DB 재적재(`load_batch`) | 스냅샷 없음 → 결과 DF 폴백 | **오염** |
| 측정 스크립트           | 결과 DF 직접 사용          | **오염** |

`featured_data`라는 필드가 "탐지 결과 컬럼 미포함"이라고 주석까지 달고 있었는데, 재탐지 경로가 그 계약을 스스로 깨고 있었다. DB 재적재 쪽은 `journal_entries` 테이블이 `anomaly_score`·`risk_level`을 저장하기 때문에 폴백만으로 오염된다.

**여기서 얻은 규칙: 아키텍처 계약은 문서에 쓰는 것으로 지켜지지 않는다.** 위 표의 "추론 독립성" 항목은 2026-07-25 시점에도 보고서에 적혀 있었지만, 그것을 강제하는 코드는 없었다. 지름길 차단은 v6·v7 감사에서 *합성 데이터의 지름길*을 잡느라 컬럼 이름을 하나하나 뒤졌는데, 정작 **자기 시스템이 만들어 넣은 출력**은 아무도 세지 않았다.

수정은 세 겹으로 했다.

1. **입력 경계 차단** — `LEAKAGE_DENY_COLUMNS_PHASE1_OUTPUT`(6칸)을 신설해 deny 목록에 합쳤다(52 → 58). 어느 스냅샷이 넘어왔는지에 의존하지 않게 만드는 것이 요점이다.
2. **근본 수정** — 재탐지가 진입 시점(탐지 전) 프레임을 `featured_data`로 고정하게 바꿨다. 탐지 후 복사는 삭제했으므로 큰 프레임 복사 한 번도 같이 없어졌다.
3. **측정 정렬** — VAE 측정 스크립트 3개가 결과 DF 대신 탐지 전 스냅샷을 쓰게 했다. 측정이 운영과 다른 입력을 보고 있었던 것 자체가 결함이다.

회귀 테스트를 붙였다 — 6칸이 deny 목록에 있고 전처리가 실제로 떨어뜨리는지 검사한다. 부수적으로 deny 개수를 하드코딩한 테스트(54)가 실제(57)와 어긋난 채 방치돼 있던 것도 드러나 상수에서 계산하도록 고쳤다. **하드코딩한 개수는 목록이 늘 때마다 조용히 stale 이 된다.**

이 결함이 앞선 것들과 다른 점이 있다. 지금까지 고친 것은 전부 합성 데이터 생성기의 아티팩트였다. **이건 제품 코드의 결함이라 실제 고객 데이터에서도 그대로 발생한다.**

## 9.5 학습 구성과 1차 관문 통과 (회차 C 조건 — 학습 20만 행, 2026-08-01)

정상 base에서 학습하고, 미학습 정상 구간의 플래그율이 오염 설정 근처인지 확인한다. **학습 조건은 9.6절 회차 C와 같다** — 입력 재설계 후, 정상 정본 20만 행, 라벨 미사용.

**다만 통과 폭이 좁아진 것을 함께 적는다.** 학습 구간 0.999% 대 미학습 1.956%로 격차가 약 2배다. 회차 A(5만 행·구 입력)에서는 0.998% 대 1.056%였다. 대역 상한 3배까지 여유가 1.5배뿐이므로, "정상을 정상으로 본다"는 진술은 통과하되 이전만큼 넉넉하지 않다. 원인 후보는 입력 차원 확대(허용 목록 전환과 원-핫 확대로 71 → 390)이며 **분해 측정은 하지 않았다 — 미검증**이다.

재현: `uv run python tools/scripts/s1_measure_vae_flagrate.py data/journal/primary/datasynth_semantic_v1_normal_s10_c001_20260717 --train-rows 200000 --out reports/s1_vae_flagrate_s10_t200k/vae_flagrate.json`

부수적으로 제품 버그도 하나 잡았다. 결측이 있는 불리언 피처가 전처리 통과 경로에서 numpy 변환에 실패해 터졌다. 불리언 전용 변환기를 신설해 결측을 부동소수 NaN으로 바꾼 뒤 최빈값으로 대치하도록 고쳤다(수치형이 중앙값 대치를 쓰는 것과 같은 결).

### 상보성 지표는 철회한다 (5차 정정, 2026-08-01)

이 자리에는 "룰이 놓친 부정 **27 / 124 (21.8%)** 회수"가 실려 있었다. **인용하지 않는다.**

경위는 이렇다. 전체 룰 기준 미표면은 r9 에서 **0~2건**이다. 놓친 것이 없으면 보완할 것도 없으므로 이 축의 지표는 성립하지 않는다. 그런데도 지표를 내기 위해 무정보 룰(lift ≤ 1.0)로만 오른 문서를 표면화에서 빼고, 미표면을 벌당 30~34건(4벌 합계 124건)으로 만들었다. 그중 27건이 VAE 상위 1%에 들었다는 것이 21.8%였다.

철회 근거가 셋이다.

| 근거                        | 내용                                                                                                                                                            |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 결과를 보고 분모를 골랐다   | 원래 분모(전체 룰)로는 지표가 나오지 않아 바꿨고, 바꾼 방향은 VAE 주장이 성립하는 쪽이다                                                                        |
| 비교 기준이 비대칭이다      | 룰 커버리지는 컷 없이 "목록 등재"로 세고, VAE는 상위 1%(1,134건) 컷으로 셌다. 같은 컷을 룰에 씌운 측정은 없다                                                   |
| 분모가 생성기 설정의 함수다 | 컷을 만든 것은 사실상 L1-07 승인생략 하나이고, 그 lift 0.64는 정상 데이터의 승인누락 비율을 그렇게 **생성했기 때문에** 나온 값이다. 설정을 바꾸면 컷이 사라진다 |

남는 것은 **AUROC 0.8845**와 **recall@top1% 0.3568**이다. 둘 다 룰과 무관하게, 전체 부정 330건을 분모로 잰 값이다.

수법 편중은 관찰로 남긴다 — 상위 1%에 오르는 부정은 FS01 가공매출과 FS05 순환거래(둘 다 없는 매출을 만드는 같은 계열)에 몰리고, 유령급여·FS08·FS12·FS13은 4벌 내내 거의 오르지 않았다. 어느 수법이 오르는가는 4벌 모두 동일해 표본 흔들림이 아니다. **"VAE가 룰을 보완한다"는 서술은 근거가 없고, "VAE가 반응하는 범위는 가공매출 계열"이라는 서술만 남는다.**

### 부정의 실체인가, 생성기 흔적인가

합성 데이터로 잰 값이므로 이 구분이 먼저다. 생성기 흔적을 배운 것이라면 실제 원장에는 그 봉제선이 없어 실전에서 무너진다. 세 가지가 "부정의 실체" 쪽을 가리킨다.

1. **회수 근거가 도메인적으로 성립한다.** 없는 매출을 만들면 인도가 없거나 증빙일과 어긋난다. 1위 칸이 정확히 그것이고, 회수가 가공매출에만 몰린 것과 앞뒤가 맞는다.
2. **배선 칸은 기여하지 않는다.** 전기시각·요일·월중일자는 평평하다. 부정 전표가 정상 전표를 복제해 만들어지므로([5장 생성기 구조](3_DATASYNTH-ENGINE.md)) 그 칸들엔 배울 것이 없다 — 설계와 측정이 일치한다.
3. **사람·승인 축이 0.1%다.** 담당자 배정에 인공적 편향이 없다는 뜻이다. 직무분리 플래그를 부정에만 넣으면 그 칸 하나가 정답지가 된다고 보고 제외했던 판단이 측정으로 뒷받침됐다.

**미확인 1건**: seed3 에서만 차입금 인출 계열이 66~77배로 튀었다. 그 벌은 미표면이 34건(다른 벌 30건)으로 구성이 다르다. 원인은 확인하지 않았다.

## 9.7 측정이 성립하지 않은 이유 — 데이터에 지름길이 실재했다

> **이 절 이하의 진단 수치는 전부 재설계 _전_ overlay(`..._20260718_r1`)의 것이다.** 여기서 특정한 결함이 2026-07-27 생성기 재설계의 출발점이 됐고, 재설계 후 데이터(`..._20260727_r9`)에서는 단독 분리자가 0종, 계정과 무관한 컬럼쌍 미출현률이 0.91%(정상 동수 대조군 0.30%)다([4.7](4_DATASYNTH-QUALITY.md)). **재측정은 2026-07-29에 마쳤다**(회차 C, [9.6](#96-2차-관문--학습-표본에-따라-결과가-뒤집혔다)) — 이 절의 AUC 값(0.660 / 0.5187 / 1.0000)은 어느 것도 현행 데이터의 값이 아니므로, 이하는 **그 결함을 어떻게 특정했는지의 기록**으로 읽는다.

원인 후보를 가르려고(EDA 부족·전처리 부족·라벨 부족·튜닝 부족) 개발셋 `..._r1_seed1`에서 먼저 단변량 분리도를 측정했다. 여기서 예상과 다른 것이 나왔다.

| 측정                         | 결과                                                |
| ---------------------------- | --------------------------------------------------- |
| 대상                         | seed1 FY2022, 119,336행 / 37,978전표 / 부정 83전표  |
| 최대 단변량 AUC              | **0.858** (`approved_by` 존재 여부에서 파생된 3종)  |
| 전표 단위 `approved_by` 존재 | 부정 **83/83 = 100%** vs 정상 10,773/37,895 = 28.4% |
| 결측률 차 5%p 초과 컬럼      | 69개 중 **16개**                                    |

**부정 전표가 생성 경로 차이로 특정 컬럼이 통째로 비거나 통째로 차 있었다.** 결측 여부 하나만 점수로 써서 부정을 얼마나 가려낼 수 있는지 재 보면 이렇게 나온다(0.5가 정보 없음, 0이나 1에 붙을수록 결측 패턴이 라벨을 그대로 말해준다).

| 컬럼                      | 결측률(부정) | 결측률(정상) | 결측만으로 AUC | 학습 입력 결정    |
| ------------------------- | -----------: | -----------: | -------------: | ----------------- |
| `is_suspense_account`     |     **100%** |       **0%** |      **1.000** | **exclude**       |
| `batch_id` / `job_id`     |         100% |        23.8% |          0.881 | 결정 기록 없음    |
| `approved_by`             |       **0%** |        72.1% | 0.139 (역방향) | **include**       |
| `debit_account_subtype`   |         100% |        48.4% |          0.758 | 결정 기록 없음    |
| `credit_account_subtype`  |         100% |        51.7% |          0.742 | 결정 기록 없음    |
| `approval_date`           |         100% |        72.1% |          0.639 | exclude           |
| `trading_partner`         |           0% |        17.0% |          0.415 | **include**       |
| `cost_center`             |        70.5% |        60.2% |          0.551 | **include**       |
| `tax_code` / `tax_amount` |        68.7% |        76.4% |          0.461 | include / exclude |

학습 입력 결정은 이 배치의 학습 리포트에서 직접 읽었다(`preprocessing_plan.decisions` **94건 — exclude 56 / include 38**). 두 가지를 정확히 해 둔다.

- **"결정 기록 없음"은 "안전하게 차단됨"이 아니다.** 컬럼 결정 94건 목록에 그 이름이 없다는 사실만 확인했다. 피처 생성 단계에서 다른 컬럼으로 흡수됐는지, 파이프라인이 일찍 떨어뜨렸는지는 미확인이다.
- **홀드아웃에서도 같다.** `..._r1`에 같은 스캔을 돌리면 14개 컬럼이 걸리고 `is_suspense_account` 결측 단독 AUC는 **1.000**으로 동일하다. seed 특유의 사고가 아니라 **생성기의 성질**이다.

### 회차 B 재측정에서 확인한 것 — 격차는 21컬럼, 차단선 밖에 여럿 남아 있다 (2026-07-26)

회차 B의 AUROC 1.000을 진단하려고 같은 스캔을 `..._r1` 전체(356,446행)에 다시 돌렸다. 이때 **층화가 필수**라는 것이 드러났다. 부정 overlay를 정상 base와 데이터셋 단위로 비교하면 결측률 차가 0.2%p 이하로 보이지 않는다 — overlay가 대부분 정상 행이라 660행의 부정이 평균에 묻힌다. 같은 파일 안에서 부정 행과 정상 행을 갈라야 나온다.

| 측정                    | 결과                                     |
| ----------------------- | ---------------------------------------- |
| 대상                    | `..._r1` 356,446행 / 부정 660행(330전표) |
| 결측률 차 5%p 초과 컬럼 | 73개 중 **21개**                         |
| 완전 분리 컬럼          | `is_suspense_account` 0% ↔ **100%**      |

전표 단위로 "이 칸이 비었는가"만 점수로 써서 부정을 가려내는 단독 판별력을, **차단 목록 소속 여부와 나란히** 재면 이렇게 갈린다.

| 컬럼                           | 차단 목록 | 결측 단독 AUROC        |
| ------------------------------ | --------- | ---------------------- |
| `is_suspense_account`          | **차단**  | **1.0000**             |
| `batch_id` · `job_id`          | 통과      | 0.8697                 |
| `approved_by`                  | 통과      | 0.1387 (역방향 0.8613) |
| `approval_date`                | 통과      | 0.6507                 |
| `debit/credit_account_subtype` | 통과      | 0.5245                 |
| `trading_partner`              | 통과      | 0.4438                 |
| `profit_center`                | 통과      | 0.4536                 |

**단독으로 완벽한 분리자는 차단 목록이 실제로 막았다.** 1차 방어는 설계대로 작동했다. 그런데 통과한 컬럼들이 각각 0.65~0.87을 들고 있고, 그중 어느 하나도 단독 1.0이 아니다. 따라서 회차 B의 1.000은 한 컬럼을 베낀 값이 아니라 **통과한 아티팩트 여러 개를 모델이 조합해 만든 값**이다. 이것이 9.8절의 기존 해석을 무너뜨린다.

### 왜 도메인이 아니라 생성 아티팩트인가

`approved_by`를 예로 든다. 부정 전표는 83/83 = 100%가 승인자를 갖고 정상은 28.4%만 갖는다. 그리고 fraud_type 9종(circular_trading·fictitious_revenue·embezzlement_cash·payroll_ghost_employee 등)이 **전부 예외 없이 100%**다.

현실에서 부정이 승인을 100% 통과하지는 않는다 — 오히려 승인 우회·자기승인이 부정의 특징이고, 이 프로젝트의 룰 어휘도 그 전제로 짜였다([7장](7_PHASE1-1_COMBO-BUILDER.md) 특징 축). 그리고 서로 다른 9개 시나리오가 한 값으로 수렴하는 것은 시나리오 고유의 성질이 아니라 **그 시나리오들을 찍어내는 공통 코드 경로**의 성질이다.

이는 이 프로젝트가 명문화한 DataSynth 규칙의 정면 위반이다 — "데이터 품질(MCAR·typo·format)은 정상/비정상 무관하게 **동일 비율** 적용. ML 지름길 학습·일반화 실패·허위 피처 중요도·합성 아티팩트 방지."

### 게이트가 왜 통과시켰나 — 거짓 PASS가 아니라 좁은 분모

지름길 게이트 16종은 대표본·seed1에서 ALL PASS였다. 게이트 코드를 열어 원인을 확인했다.

| 축                | 분모                                                                                   | 이 결함을 잡지 못한 이유                                                  |
| ----------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| S1 메타 결측률 차 | 메타 컬럼 **8개**(`user_persona`·`cost_center`·`line_text`·`header_text` 등), 임계 8%p | 위 표의 컬럼 대부분이 이 8개에 없다                                       |
| S2 단일피처 분리  | 31컬럼 × (각 값 + `IS NULL`), 정밀도·recall 기준                                       | "채워져 있으면 부정"이라는 **`IS NOT NULL` 쪽 집중은 판정 형태가 아니다** |

`is_suspense_account`·`batch_id`·`job_id`·`debit/credit_account_subtype`·`approval_date`는 두 분모 어디에도 없다. `approved_by`는 S2 분모에 있지만 S2가 보는 형태(값별 정밀도, `IS NULL`의 정밀도)로는 "부정이 100% 채워져 있다"가 걸리지 않는다.

**게이트가 거짓 PASS를 낸 것이 아니라 선언한 범위를 지켰고 그 범위가 좁았다.** [4장](4_DATASYNTH-QUALITY.md) §4.2가 "현실성 카탈로그 146축 중 게이트 구현 49개(34%)"라고 적어 둔 한계의 구체적 대가이며, 그 절이 함께 적은 전략("룰이 읽지 않는 축의 비현실은 결과에 영향 없다")이 **ML에는 적용되지 않는다**는 것이 이번에 드러난 사실이다. 룰은 컬럼을 골라 읽지만 ML은 주어진 컬럼을 다 본다.

## 9.8 낮은 수치를 어떻게 읽었고, 그 읽기가 왜 틀렸나

지름길이 실재했다면 점수는 부풀어야 했다. 부풀지 않았다. 홀드아웃(`..._r1`, 3,368전표 / 부정 47)에서 세 숫자를 나란히 놓으면 순서가 뒤집혀 있다.

| 점수                                                 |        AUC |
| ---------------------------------------------------- | ---------: |
| `is_suspense_account` 결측 여부 (**차단된** 지름길)  |  **1.000** |
| `approved_by` 유무 단독 (**통과한** 지름길, include) | **0.7928** |
| VAE 전표 점수 (include 38컬럼 학습)                  | **0.6599** |

> 여기의 "38컬럼"은 이 배치(`fraud_test` / FY2022) 학습 리포트의 컬럼 결정 94건 중 include 수이며, 9.5절의 "피처 71"은 정상 base 학습 실행의 확장 후 피처 수다. 세는 단위(원본 컬럼 vs 인코딩 확장 피처)와 실행이 다른 값이므로 두 숫자를 비교하면 안 된다.

컬럼 하나의 결측 여부가 모델 전체보다 잘 맞춘다. 그리고 학습 입력에 실제로 들어간 지름길(`approved_by`)조차 점수가 따라가지 않았다.

| 측정                               | 값                          |
| ---------------------------------- | --------------------------- |
| VAE 점수 ↔ `approved_by` 유무 상관 | **-0.0493** (사실상 무상관) |
| 승인자 있는 전표의 VAE 점수 평균   | 0.97695                     |
| 승인자 없는 전표의 VAE 점수 평균   | 0.97829                     |

두 군의 평균 차이는 0.0013이다. 당시 이유를 둘로 적었다.

- **가장 강한 지름길은 deny 목록이 입력 전에 잘라냈다.** `is_suspense_account`는 `LEAKAGE_DENY_COLUMNS`에 명시돼 있고 이 배치의 학습 결정도 `exclude`였다. 9.3절의 1차 방어가 설계대로 작동했다.
- **통과한 지름길도 비지도 구조가 성능으로 환산하지 못했다.** VAE는 라벨을 보지 않으므로 "어느 방향이 부정인가"를 모른다. 정상 분포를 재구성하도록만 학습하니, 라벨과 상관된 컬럼이 입력에 있어도 그것을 부정 판별에 동원할 방법이 없다.

### 둘째 이유는 반증됐다 — 표본 5만 행에 얹혀 있던 해석이었다 (2026-07-26)

회차 B에서 **deny 설정을 한 줄도 바꾸지 않고 학습 표본만 4배로 올렸더니 AUROC가 1.000이 됐다.** 그러므로 "비지도 구조는 통과한 지름길을 성능으로 환산하지 못한다"는 구조적 주장이 아니었다. 표본이 적어 환산하지 못하고 있었을 뿐이고, 표본이 늘자 환산했다.

| 주장                               | 판정                                                                       |
| ---------------------------------- | -------------------------------------------------------------------------- |
| 최강 지름길은 차단 목록이 막았다   | **유지** — 회차 B에서도 `is_suspense_account` 단독 1.0000, 입력에서 제외됨 |
| 비지도 구조가 지름길을 못 쓴다     | **반증** — 같은 차단 설정에서 표본만 늘려 1.000 달성                       |
| 낮은 수치 = 방어가 작동했다는 신호 | **조건부로 격하** — 5만 행이라는 학습 조건에 의존한 해석이었다             |

상관 −0.0493도 5만 행 모델의 값이라 회차 B에 전용할 수 없다. 회차 B 모델에 대한 같은 상관 측정은 미실시다.

정정된 읽기는 이렇다. **차단 목록은 자기 일을 했고, 낮은 점수를 만든 것은 방어가 아니라 학습 부족이었다.** 통과한 아티팩트(승인자 유무·배치 번호·계정 하위유형 결측)는 처음부터 조합 가능한 상태로 입력에 있었고, 모델이 정상 분포를 충분히 배우자 그 조합을 그대로 이용했다.

같은 데이터로 **지도학습**을 돌렸다면 `approved_by` 하나로 AUC 0.79, deny가 없었다면 `is_suspense_account`로 1.0에 근접한 수치가 나왔을 것이다. 그 수치는 전부 자문자답이다 — 구세대 데이터의 AUROC 0.93이 "흔적을 심고 자기가 심은 것을 찾은" 값으로 무효화된 경로가 정확히 그것이다. **회차 B의 1.000이 비지도 경로에서 같은 일이 일어난 실측 사례다.**

여기서 선을 분명히 그어야 한다. 낮은 수치를 방어의 성과로 읽는 것도, 높은 수치를 성능으로 읽는 것도 같은 종류의 세탁이다. 0.5187·0.66·1.000 **어느 것도 성능 증거가 아니다.**

이 절을 쓴 시점에는 여기에 "이 데이터로는 증명할 수도 반증할 수도 없다"를 덧붙였다. **그 문장은 2026-07-29에 절반이 틀린 것으로 드러났다** — 데이터를 고치고([9.3.2](#932-차단-근거-전수-재검--58칸에서-22칸으로-2026-07-29)) 입력 배관을 고친 뒤 재측정하니 재현 가능한 0.8845가 나왔고, 무엇을 보고 올렸는지도 기여 분해로 특정됐다([9.6.1](#961-무엇을-보고-올렸나--기여-분해)). 증명할 수 없었던 것은 데이터의 성질이 아니라 **당시의 입력과 측정**이었다.

## 9.9 판정 정정 — 무엇이 바뀌고 무엇이 남았나

판정은 네 차례 고쳐졌다. 2026-07-25에 라벨을, 2026-07-26에 낮은 수치의 해석을, 2026-07-27에 **"생성기를 고치지 않는다"는 결정 자체**를, 2026-07-29에 **판정 이름과 성능 주장의 범위**를 고쳤다. 아래 표는 1~2차까지이고, 3차·4차는 이어지는 두 절이다.

| 항목             | 최초 판                             | 1차 정정 (07-25)                                  | 2차 정정 (07-26)                                                     |
| ---------------- | ----------------------------------- | ------------------------------------------------- | -------------------------------------------------------------------- |
| 측정 수치        | AUROC 0.5187 / recall@top1% 0.0038  | 그대로 (+ 단일 배치 0.6599, CI [0.579, 0.733])    | 그대로 (+ **회차 B 20만 행 1.0000 / recall 1.0000**)                 |
| 판정 이름        | 행 단위 VAE **검증 실패**           | **성능 검증 불성립 — 측정 데이터 무효**           | **불변** — 증거만 늘었다                                             |
| 낮은 수치의 해석 | 모델이 못 잡았다                    | 오염된 데이터에서 점수가 부풀지 않았다(방어 작동) | **학습 표본 부족이었다.** 방어 성과로 읽은 것은 5만 행 조건의 산물   |
| 원인 설명        | 완전 위장 → 행 단위에 **정보 부재** | 정보는 있었고 그 정보가 **생성 아티팩트**였다     | 불변 + **아티팩트가 조합 가능한 상태로 입력에 남아 있었다**          |
| 학습 표본 상한   | 5만 행 (근거 미기록)                | 언급 없음                                         | **근거 없음을 확인해 20만 행으로 상향**. 이 상향이 2차 정정을 낳았다 |
| VAE 성능 주장    | 하지 않음                           | 하지 않음                                         | **하지 않음 (불변)** — 1.000도 성능 근거로 쓰지 않는다               |
| 표면의 역할      | 보조 — 정상 밖 비정형 후보 제시     | 불변                                              | **불변**                                                             |

### 실패는 사라지지 않고 옮겨갔다

라벨을 고쳐도 실패 항목은 줄지 않는다. 위치가 바뀐다.

- **여전한 실패**: 합성데이터 경로로 비지도 탐지 성능을 증명하려는 시도. 딜레마가 이번에 3분기로 늘었다.

```
    흔적을 심는다      ──▶ 자기가 심은 것을 자기가 찾음 (자문자답)   ↓ 성능 증거 아님
    흔적을 안 심는다    ──▶ 정보가 없어 못 잡음                      ↓ 성능 증거 아님
    안 심으려 했는데
    게이트 밖에서 남았다 ──▶ 측정 자체가 무효 (본 실측)              ↓ 성능 증거 아님
```

- **새로 드러난 실패**: DataSynth 규칙 위반(부정·정상 결측 패턴 불일치)을 **게이트 3겹이 전부 통과시켰다.** 1겹 게이트 57종은 분모에 없었고, 2겹 룰 발화율은 룰이 읽지 않는 컬럼이라 신호를 남기지 않았고, 3겹 지름길 게이트는 결측률 축의 분모가 8컬럼이었다. 이것이 이번 라운드의 실질적 실패이며 조치 대상이다.

- **PHASE1 쪽으로도 번졌다**: 승인 데이터 유무는 VAE 입력이기만 한 것이 아니라 **여러 룰의 판정 입력**이다. 층화 검사에서 승인 의존 룰의 부정·정상 대비가 사라지거나 역전됨을 확인했고, 특히 **L1-07 승인생략은 부정 표면화가 0.000**이었다(부정이 100% 승인자를 가지므로 발화 불가). 표면 커버리지 자체는 승인 축 밖 룰이 이끌어 방향이 유지되지만, 밀도·대비 수치는 상한으로 격하했다([7.8](7_PHASE1-1_COMBO-BUILDER.md)).

- **취소되지 않는 것**: 이전 라운드가 이 수치를 실패로 **기록해 둔 행위**는 옳았다. 라벨이 부정확했을 뿐 수치를 숨기지 않았고, 그래서 이번에 그 수치를 다시 들여다볼 수 있었다.

### 3차 정정 (2026-07-27) — 고치지 않기로 한 결정을 뒤집었다

"생성기를 고쳐도 인용할 수 없는 수치 하나가 남을 뿐"이라는 판단으로 마감했으나, **그 판단의 전제가 틀렸다.**

전제는 "누출을 지워도 합성 라벨의 자기참조 때문에 어차피 못 쓴다"였다. 그런데 실제로 결측 오라클을 지우고 나니 **더 큰 누출이 드러났다** — 컬럼 **쌍**의 조합이다. 부정 행의 100%가 정상 원장에 한 번도 없는 컬럼 조합을 하나 이상 갖고 있었다(정상 동수 대조군 0.79%). 첨부가 없다는데 증빙 종류가 있고, 적요가 "매입세액"인데 계정은 매출인 식이다. 이 장이 §9.11에서 "차단 기준이 단일 컬럼 판별이라 조합 축을 보지 못했다"고 쓴 바로 그 지점이, 진단에서 그치지 않고 **고칠 수 있는 결함**이었다.

원인은 하나였다. 부정 전표를 빈 껍데기에 조립한 뒤 정상 전표에서 칸을 베껴오고, 그 위에 인공 결측을 다시 뿌리고, 일부 칸을 사후 강제하고, 빈 칸을 무관한 행에서 메꿨다. **세 땜질이 전부 도너 매칭이 느슨해서 붙어 있었고**, 매칭을 제대로 하니 셋 다 함수째로 지울 수 있었다([3.7](3_DATASYNTH-ENGINE.md)).

| 지표                      | 재설계 전 | 재설계 후 | 정상 동수 대조군 |
| ------------------------- | --------: | --------: | ---------------: |
| 단독 분리자(정밀도 0.99+) |       4종 |   **0종** |                — |
| 계정 무관 컬럼쌍 미출현률 |    91.97% | **0.91%** |            0.30% |
| 계정 관련 조합 차이       |      100% |     39.2% |            0.10% |

남은 39.2%는 지우지 않는다. 부정 시나리오 절반이 정상에 없는 계정 조합을 쓰고(가지급금 경유 횡령·가수금 부채 은닉·유령급여), **그 조합이 곧 부정의 실체**이며 L4-04 희소계정쌍 룰이 잡는 신호다.

**이 시점에 남긴 숙제는 재측정이었다** — "1.0000이 여전히 나오는가, 나온다면 이번엔 무엇을 학습한 것인가". 그 숙제는 다음 절(4차 정정)에서 마쳤고, 답은 둘 다 아니었다: 1.0000은 나오지 않았고(0.8845), 학습한 것은 아티팩트가 아니라 인도일 간격·금액·거래 유형이었다.

PHASE1 쪽은 재측정을 마쳤다 — 승인 계약이 정상 분포를 따르게 되면서 L3-09 가수금 체류가 0 → 35문서/벌로 살아났고, 시각 고정 해제로 L3-06 심야가 0% → 18.2%가 됐다. 표면 커버리지는 99.4~100%(판별력 있는 룰만 89.7~90.9%)다([7.8](7_PHASE1-1_COMBO-BUILDER.md)).

### 4차 정정 (2026-07-29) — 재측정했고, 폐기 조건에 걸리지 않았다

3차 정정이 남긴 숙제("재측정 후에야 무엇을 학습한 것인지 물을 수 있다")를 마쳤다. 그런데 재측정 전에 **입력 자체가 잘못돼 있던 것이 먼저 드러났다** — 제품과 측정이 서로 다른 전처리 경로를 탔고([9.3.1](#931-3중-방어--이제-2차-방어다)), 입력에 PHASE1 룰용 파생 39칸이 흘러들어 있었으며([9.3.0](#930-무엇이-들어오는가는-허용-목록이-정한다-2026-07-29-전환)), 금액 차단의 근거가 2개월 전 데이터 기준이었다([9.3.2](#932-차단-근거-전수-재검--58칸에서-22칸으로-2026-07-29)). 전처리 15건을 고친 뒤 잰 값이 회차 C다.

| 항목            | 3차 정정까지                         | **4차 정정 (07-29)**                                                                           |
| --------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------- |
| 측정 수치       | 20만 행 1.0000 (아티팩트)            | **4벌 평균 0.8845** · 시드 고정으로 재현                                                       |
| 판정 이름       | 성능 검증 불성립 — 측정 데이터 무효  | **폐기 조건 불성립 — 표면을 유지한다**                                                         |
| 성능 주장       | 하지 않음                            | **수법 단위로만 한다** — 가공매출 34% 회수, 다른 계열 0%                                       |
| 무엇을 학습했나 | 미확인 (숙제로 남김)                 | **인도일 간격·금액·거래 유형** — 기여 분해로 확인([9.6.1](#961-무엇을-보고-올렸나--기여-분해)) |
| 아티팩트 여부   | 미확인                               | **아니다** — 배선 칸 기여 없음, 사람·승인 축 0.1%                                              |
| 상보성          | 측정 불가(전체 룰 기준 미표면 0~2건) | 27 / 124 (21.8%) — 분모 교체. **5차 정정에서 철회, "측정 불가"로 되돌아감**                    |
| 재현성          | **없음** — 시드 미고정               | **있음** — `torch.manual_seed(42)`                                                             |

**폐기 조건은 이 라운드 착수 시점에 미리 못 박아 두었다** — *"판별력이 무작위 근처거나, PHASE1-1이 이미 올린 것 위에 추가로 올리는 게 없으면 증거를 갖고 폐기한다."* 결과를 보고 기준을 만들면 어떤 값이든 정당화되므로 순서를 지켰다.

| 폐기 조건                         | 실측                      | 판정          |
| --------------------------------- | ------------------------- | ------------- |
| 판별력이 무작위 근처인가          | AUROC 0.8845 (무작위 0.5) | 아니오        |
| PHASE1-1 위에 더 올리는 것이 없나 | 전체 룰 기준 미표면 0~2건 | **판정 불가** |

**두 번째 조건은 판정하지 못했다 (5차 정정, 2026-08-01).** 2026-07-29 판은 이 칸을 "아니오(미표면 124건 중 27건 회수)"로 채웠으나, 그 124건은 무정보 룰을 사후에 빼서 만든 분모였다. 원래 분모로는 룰이 놓친 것이 0~2건이라 **잴 대상이 없다** — "더 올리는 게 없다"가 확인된 것도, "있다"가 확인된 것도 아니다.

그래서 지금 표면을 유지하는 근거는 **첫 번째 조건 하나뿐이다.** 판별력이 무작위와 뚜렷이 다르다는 것. 두 번째 조건은 이 데이터셋에서 판정할 수 없으므로, 상보성을 근거로 표면을 정당화하지 않는다.

이 정정이 앞의 셋과 다른 점은 **처음으로 판정이 좋아진 방향으로 움직였다**는 것이다. 그리고 그 이유가 모델이 아니라 입력이었다 — 3차 정정까지의 실패는 데이터 결함이었고, 4차에서 드러난 것은 **입력 배관 결함**이었다. 모델은 한 줄도 바꾸지 않았다.

### 원인 후보 네 가지의 처분

| 후보                 | 처분                                                                                                                                                                                                                                               |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EDA 부족             | **원인 아님** — EDA를 했더니 데이터 결함이 나왔다. 이 절이 그 산출물이다                                                                                                                                                                           |
| 전처리 부족          | **절반만 방어 성공** — deny가 최강 지름길(단독 1.0000)은 차단했다. 그러나 `batch_id`·`job_id`·`approved_by`·`approval_date`·계정 하위유형이 통과했고, 회차 B는 이 통과분을 조합해 1.000을 만들었다. deny 보강 여지는 여지가 아니라 실제 구멍이었다 |
| **학습 표본 부족**   | **낮은 수치의 원인은 이것이었다** — 5만 행에서 0.5187, 같은 설정에서 20만 행이면 1.0000. 다만 이것은 "표본을 늘리면 성능이 나온다"가 아니라 **"표본을 늘리면 아티팩트를 쓴다"**는 뜻이다                                                           |
| 정답(부정 라벨) 부족 | **부차적** — 부정 47건으로 CI 폭 0.154는 실재하는 문제지만, 표본을 늘려도 **오염된 수치를 더 정밀하게 재는 것**에 불과하다. 비지도라 오버샘플링은 해당 없음                                                                                        |
| VAE 튜닝 부족        | **하면 해롭다** — 튜닝 기준으로 삼을 AUC 자체가 오염돼 있다. 이 데이터로 수치를 올리면 지름길 학습을 유도한 결과이고 성능 증거가 못 된다. 회차 B가 이 경고의 실측 사례다                                                                           |

다섯 후보 중 "학습 표본 부족"만 실제 원인으로 확인됐고, 그 확인이 상황을 **개선하지 않았다.** 표본을 늘려 얻은 것은 성능이 아니라 아티팩트 이용이었다.

**이 표에 없던 여섯 번째 후보가 실제 원인이었다 — 입력 구성이다.** 다섯 후보는 전부 "모델·데이터·라벨·튜닝" 축이고, "무엇이 입력으로 들어가는가"는 아무도 세지 않았다. 실제로는 PHASE1 룰용 파생 39칸이 흘러들어 있었고([9.3.0](#930-무엇이-들어오는가는-허용-목록이-정한다-2026-07-29-전환)), 그중 6칸이 PHASE1 탐지 산출물이었고([9.4](#그-마지막-항목은-주장이었고-코드가-지키지-않았다-2026-07-28)), 원장의 핵심인 차대변 금액은 두 달 전 근거로 막혀 있었다([9.3.2](#932-차단-근거-전수-재검--58칸에서-22칸으로-2026-07-29)). 후보 목록을 세울 때 **파이프라인의 입구를 후보로 넣지 않은 것**이 이 라운드의 진단 실패다.

### 이력 — 고치지 않기로 했던 결정과 그 근거 (2026-07-25, 07-27에 뒤집힘)

> **이 절은 폐기된 결정의 기록이다.** 아래 근거 셋 중 둘이 틀렸고, 2026-07-27에 생성기를 근본부터 고쳤다(3차 정정). 남겨 두는 이유는 판단이 어디서 어긋났는지가 이 장의 교훈이기 때문이다.

가장 자연스러운 다음 행동은 생성기를 고쳐 결측 패턴을 동일화하고 다시 재는 것이다. **그렇게 하지 않기로 결정했다.** 근거가 셋이었다.

| 근거                        | 내용                                                                                                                                                                                                                                                |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 고쳐서 지킬 것이 없다       | 이 보고서 본문의 검증 수치(발화율 대역·룰 단위시험·빌더 정확성 판정)는 **다른 데이터셋** 기반이라 이 결함의 영향권 밖이다. 표면 커버리지만 이 overlay 기반이며, 그 값은 별도의 측정 경로 결함으로 이미 내려갔다([7.8](7_PHASE1-1_COMBO-BUILDER.md)) |
| 이 데이터셋엔 판별력이 없다 | any-rule 축에서 부정 **96.4~98.5%** vs **정상 98.8%**(4벌 실측) — 룰이 거의 전 전표에 발화하므로 이 데이터로는 VAE든 룰이든 대비를 만들 수 없다                                                                                                     |
| 고쳐서 얻는 것이 주장 불가  | 산출물은 "더 그럴듯한 합성 수치" 하나인데, 그 수치는 합성 라벨의 자기참조 딜레마 때문에 **애초에 성능 주장에 쓸 수 없다**(9.9절 3분기 도식)                                                                                                         |

즉 수정 비용은 Rust 생성기 재작업 + 2.5GB 재생성 + 게이트 재정비인데, 얻는 것은 인용할 수 없는 숫자다. **그래서 여기서 멈춘다.**

대신 딱지를 붙였다. **구 overlay(`..._20260718_r1` 계열)는 성능 측정 부적격(not fit for performance measurement)**이며, [4장](4_DATASYNTH-QUALITY.md) §4.7 데이터셋 표에도 같은 표기를 달았다. 목적은 하나였다 — 나중에 누가(작성자 자신을 포함해) **0.5187·0.660·1.000 중 어느 것도 성능으로 인용하지 않게** 하는 것. **이 딱지는 지금도 유효하다.** 뒤집힌 것은 "그래서 생성기를 고치지 않는다"는 후속 결정이고, 구 데이터셋의 부적격 판정 자체는 그대로다.

두 근거가 틀린 지점은 이렇다. "고쳐서 얻는 것이 주장 불가"는 결측 오라클만 지운다는 전제였는데, 실제로 지워 보니 **컬럼 쌍 조합**이라는 더 큰 누출이 그 아래 있었다([9.9 3차 정정](#3차-정정-2026-07-27--고치지-않기로-한-결정을-뒤집었다)). "이 데이터셋엔 판별력이 없다"는 any-rule 축의 관측이었는데, 재설계 후 r9 에서는 판별력 있는 룰 기준으로 대비가 만들어졌다([7.8](7_PHASE1-1_COMBO-BUILDER.md)).

## 9.10 네 라운드가 남긴 것

**표면의 역할은 다섯 차례 정정을 통과하고도 그대로다.** VAE는 "학습된 정상 밖 비정형의 추가 검토 후보 제시"라는 보조 역할이며, PHASE1 룰과 점수를 합치지 않는다. 4차 정정에서 판별력이 확인된 뒤에도 이 위치를 올리지 않았고, 5차 정정에서 상보성 근거가 빠진 뒤에는 더더욱 올릴 이유가 없다.

**"룰을 보완한다"는 주장은 하지 않는다.** 룰이 330건 중 328~330건을 목록에 올리므로 보완을 잴 대상 자체가 0~2건이다. 남는 진술은 **"판별력이 무작위와 다르다"**와 **"반응 범위가 가공매출 계열에 몰린다"** 둘뿐이고, 어느 쪽도 감사인에게 "룰이 놓친 것을 이걸로 건진다"는 기대를 주지 않는다.

**업계 실무와의 정합성을 확인했다.** 빅4 도구를 조사한 결과는 이렇다.

| 도구           | 방식                      |
| -------------- | ------------------------- |
| EY Helix GLAD  | 감사인 라벨 기반 지도학습 |
| KPMG Clara     | 룰·기준 분석 위에 ML 보조 |
| PwC Halo       | 룰 묶음 + 의심 점수       |
| Deloitte Omnia | 기준 기반 분석            |

네 도구 모두 룰·기준이 주력이고 ML은 보조이며, **비지도 딥러닝 단독 탐지는 실무에 없다.** 본 프로젝트의 구조(결정론 룰이 주 표면, VAE는 병합하지 않는 보조)는 이 관행 안에 있다.

**측정 인프라는 유지하되 한계를 안다.** 평가 방어 장치(그룹 분할 강제, 누출 게이트, 순환 라벨 차단, 컬럼 deny)는 실데이터가 유입되면 그대로 쓸 수 있다. 다만 컬럼 deny 하나로는 **충분하지 않았다** — 단독 완전 분리자는 막았지만, 개별로는 완전하지 않은 아티팩트 여러 개가 통과해 조합으로 1.000을 만들었다. 차단 기준을 "단일 컬럼 AUROC"로 잡은 설계가 조합을 보지 못한다는 뜻이다. 2026-07-29에 이 구멍을 **허용 목록**으로 우회했다 — 무엇을 막을지 세는 대신 무엇을 넣을지 선언하게 바꿨고([9.3.0](#930-무엇이-들어오는가는-허용-목록이-정한다-2026-07-29-전환)), deny 목록은 그 허용 목록의 가드레일로 남았다. 조합 축을 직접 판정하는 장치는 여전히 없다.

**실패한 지표를 화면에 그대로 띄웠다.** 2026-07-25에 VAE 탭에 ROC 곡선을 붙였다(AUC·부정 전표·평가 전표·부정 비율 카드 포함). 좋은 숫자가 나오지 않는 지표를 감추는 편이 보기에 낫지만, 이 표면이 무엇을 하는지 감사인이 판단하려면 **얼마나 못 맞히는지가 보여야** 한다. 곡선 옆에 "VAE는 학습에 라벨을 쓰지 않으며 성능 검증에만 사용한다"와 라벨 출처를 함께 적었다. 라벨이 없어 곡선을 그릴 수 없을 때도 "부정 라벨이 없다"·"원본 파일을 못 찾았다"·"`document_id`가 맞물리지 않는다"를 각각 다른 문장으로 구분한다.

> 화면에 뜨는 AUC는 그 배치의 점수 부여 전표만 대상이고 **구 overlay·구 입력 시절의 값**이므로, 그대로 인용하지 않는다([11장](11_DASHBOARD.md) 11.7). 인용 가능한 값은 회차 C의 4벌 평균 0.8845 하나이며, 화면 숫자는 배선이 동작한다는 증거로 읽는다.

## 9.11 실증 예시 — 컬럼 하나로 부정이 완벽히 갈린다

`is_suspense_account` 컬럼 하나를 따라가면 이 장의 논지가 한 줄로 보인다.

이 컬럼은 "가계정인가"를 나타내는 불리언이다. 홀드아웃 데이터에서 값을 보지 않고 **비어 있는지만** 확인하면 이렇게 갈린다 — 부정 전표는 100%가 비어 있고 정상 전표는 0%가 비어 있다. 그래서 "비었으면 부정"이라는 한 줄 규칙의 AUC가 **1.000**이다. 완벽한 분류기다.

물론 이것은 감사 신호가 아니다. 가계정 플래그가 비어 있다는 것은 그 전표가 부정이라는 뜻이 아니라, **그 전표를 만든 코드 경로가 이 필드를 채우지 않았다**는 뜻이다. 부정 overlay를 얹는 생성 경로가 정상 base 경로와 달랐고, 그 차이가 컬럼의 빈칸으로 남았다. 감사인에게 "가계정 칸이 비었으니 부정입니다"라고 말할 수는 없다.

이 컬럼은 **VAE 입력에 들어가지 않았다.** `LEAKAGE_DENY_COLUMNS`에 명시돼 있고 이 배치의 학습 결정도 `exclude`였다. 치트루트 감사(2026년 상반기)에서 단일 컬럼 AUROC 0.95 이상으로 걸러 deny에 넣어 둔 것이 이번에도 같은 일을 막았다. 만약 들어갔다면, 그리고 지도학습을 돌렸다면 AUC는 1.0 근처가 나왔을 것이고 그 숫자는 **"우리가 파일을 안 채운 것을 우리 모델이 찾아낸" 값**이었을 것이다.

같은 데이터에서 통과한 지름길도 있다. `approved_by`는 include로 학습에 들어갔고 단독 AUC가 0.7928인데, 5만 행 모델의 점수와는 상관이 -0.0493이었다. 당시에는 이것을 "비지도 모델은 어느 방향이 부정인지 몰라 그 정보를 못 쓴다"로 읽었다.

**그 읽기는 학습 표본을 20만 행으로 올리자 무너졌다.** 같은 차단 설정에서 표본만 늘렸더니 4벌 전부 AUROC 1.000이 나왔다. 방향을 몰라서 못 쓴 것이 아니라, 정상 분포를 덜 배워서 못 쓰고 있었을 뿐이다. 충분히 배운 모델은 통과한 아티팩트들의 조합이 정상에서 한 번도 나타나지 않는 형태임을 알아보고 그대로 이용했다.

정정된 요약은 이렇다. 차단된 지름길 1.000 · 통과한 지름길 0.87 · **5만 행 모델 0.52 → 20만 행 모델 1.000.** 첫 줄은 방어가 막았고, 둘째 줄은 방어를 통과했고, 셋째 줄은 그 통과분을 얼마나 배웠느냐에 따라 움직였다. 네 숫자 중 **어느 것도 "모델이 부정을 알아봤다"가 아니다** — 마지막 숫자가 가장 높지만, 그것이 알아본 것은 부정이 아니라 우리가 파일을 안 채운 자리다.

**이 컬럼은 지금 어떻게 됐나.** 2026-07-27 재설계로 결측 격차가 사라져 단독 분리자에서 빠졌고, 2026-07-29 차단 근거 전수 재검에서 **차단이 해제돼 입력에 들어왔다**([9.3.2](#932-차단-근거-전수-재검--58칸에서-22칸으로-2026-07-29)) — 불리언 0/1로 처리된다([9.3.4](#934-컬럼별-전처리--무엇을-어떻게-넣는가)). 정답지였던 칸이 정보 칸이 된 것이고, 그 전환을 가능하게 한 것은 모델이 아니라 생성기 수정이었다. 회차 C 기여 분해에서 이 칸은 상위에 없다 — 모델이 실제로 본 것은 인도일 간격과 금액이었다([9.6.1](#961-무엇을-보고-올렸나--기여-분해)).

그리고 같은 전표를 **PHASE1 룰은 잡는다.** 비용자산화 룰은 "비용 성격 지출이 자산 계정에 기표됐다"는 계정 간 **관계**를 보기 때문이다. 그 관계는 컬럼이 채워졌는지 비었는지와 무관하며, 생성 경로가 바뀌어도 남는다. 이것이 결정론 룰을 주 표면으로 두는 이유다 — 룰은 **무엇을 보는지 선언하고 그것만 본다.**

## 9.12 실세계는 이것을 어떻게 하나

행 단위 비지도 탐지가 여기까지 온 것을 "데이터가 부족했다" 또는 "튜닝이 모자랐다"로 읽으면 오독이다. 실세계 금융 이상탐지의 작동 방식과 대조하면 이 표면의 위치가 드러난다.

핵심 사실: **실무는 원시 전표 한 줄을 모델에 넣지 않는다.** 신호는 원시 행이 아니라 가공한 피처와 맥락에 있다.

| 도메인             | ML/DL이 되는가  | 이유                                                                                                         |
| ------------------ | --------------- | ------------------------------------------------------------------------------------------------------------ |
| 신용카드 부정      | **잘 된다**     | "카드 30일 평균 대비 금액", "직전 거래와의 거리·시간", 가맹점 위험도 등 **행동·속도 피처** + **대량 실라벨** |
| 자금세탁(AML)      | 보조적          | **규칙 + 관계망(그래프) + 사람 리뷰**가 주력. 라벨 희소·불확실, ML은 랭킹 보조                               |
| 재무제표·전표 부정 | **가장 어렵다** | 부정이 정상처럼 위장돼 원시 행엔 신호가 적고, 집계 분석·교차대사·원장 밖 맥락에서 신호가 나온다              |

신용카드가 되는 이유는 딥러닝이 마법이어서가 아니라, **신호를 담은 행동·속도 피처를 사람이 설계**하고 **막대한 실제 라벨**로 지도학습하기 때문이다. 전표 부정에는 그 세 조건(가공 피처·실라벨·원시 행 신호)이 모두 약하다.

그리고 이 프로젝트는 [1장](1_OVERVIEW.md)에서 **단일 법인 원장으로 스코프를 확정하며 거래처 마스터·은행·관계망·외부 대사를 데이터에서 제외**했다. 실무 부정탐지가 기대는 관계·집계·외부 신호가 데이터에 **원리적으로 부재**하도록 스스로 선을 그은 것이다(그 선은 감사 계약이 법인 단위라는 현실에 근거한 옳은 결정이었다). 여기에 합성 라벨의 딜레마(9.9절)가 겹친다.

따라서 조건이 곱해진다: **가장 어려운 도메인 × 업계도 안 쓰는 방법(원시 행 비지도) × 신호가 사는 데이터를 스코프에서 제외 × 측정에 쓸 합성 라벨의 자기참조.** 데이터를 고쳐 재측정해도 앞의 세 조건은 그대로 남는다.

**회차 C가 이 곱을 뒤집지 않는다.** 0.8845는 이 네 조건 위에서 나온 값이고, 회수가 한 수법 계열에만 몰린 것이 그 조건의 얼굴이다 — 가공매출은 "없는 매출을 만들면 인도가 없다"가 **원시 행에 남는** 드문 수법이라 잡혔고, 유령급여처럼 원장 밖 대사가 필요한 수법은 4벌 내내 0건이었다. 즉 회차 C가 보여준 것은 "원시 행 비지도가 된다"가 아니라 **원시 행에 흔적이 남는 좁은 구간에서만 된다**는 것이다.

역으로, 업계가 실제로 쓰는 방식 — **도메인 지식을 규칙으로 명시하고 그 위에 검토 우선순위를 세우는 것** — 은 이 프로젝트의 [PHASE1 룰 엔진](6_PHASE1-1_RULES.md)과 [조합 빌더](7_PHASE1-1_COMBO-BUILDER.md)가 이미 구현한 것이다. 즉 "되는 쪽"은 만들었고, "안 되는 쪽"은 어디까지 되고 어디서부터 안 되는지를 측정으로 갈라 기록했다. 낮은 수치가 유리하게 재해석될 수 있는 국면에서도 성능 주장으로 바꾸지 않았고, **판별력이 확인된 국면에서도 주장 범위를 수법 단위로 좁힌 것**이 이 장의 규율이다.
